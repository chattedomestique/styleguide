Dialog

Stop and decide. One question over a dimmed screen, answered with buttons that say what they do. The browser’s own dialog keeps focus inside and gives it back.

5
  1. 1
    Scrim::backdrop --scrim

    A flat near-black at 60% in both schemes, the one translucency the system allows: the deck is still there, but not now. The page behind is inert: no taps, no Tab, nothing for a screen reader. A tap on it does nothing; a decision needs a button.

  2. 2
    Surface.dialog <dialog>

    A container, so square: a 2px frame on paper and no shadow, since a shadow means “press this”. Centred, at most 28rem wide, 16px clear of the screen’s edges; taller than the screen, it scrolls inside. Under forced colours the scrim is gone, so the frame goes to 4px.

  3. 3
    Title.dialog__title

    The question, in an h2 that names the dialog (aria-labelledby): “Delete Shapes?”, never “Are you sure?”. A failure may lead with ic--warning.

  4. 4
    Text.dialog__text

    What follows from the answer, or what happened and what to do, in a sentence or two. It describes the dialog (aria-describedby).

  5. 5
    Actions.dialog__actions <form method="dialog">

    Buttons that say the action; each closes the dialog with its value. The safe one is primary, last, and focused first. The destructive one is a plain button whose words carry it. Narrow, they stack full width with the primary on top.

02

Variants

Three questions, each drawn as it looks and live under it. The button opens the real modal, which fades and settles in: Tab stays inside, Escape closes (even mid-entrance), and focus goes back to the button as it fades out.

2.1

Confirm

A choice that can’t be taken back: deleting a deck.

.dialog role="alertdialog" .dialog__actions autofocus

Keep it is primary and has autofocus, so Return keeps the deck. Delete deck is a plain secondary button: never primary, never red; its words say what goes. The opener’s ellipsis promises the question.

With a field

One value to type before it goes on: renaming a deck.

.form--inline .field .dialog__actions form="…-cancel"

Form’s inline form, with the actions as its last row. Focus starts in the field; Return renames. An empty name gets Field’s error and the dialog stays open. Cancel belongs to a second, empty method="dialog" form, so Return in the field can’t reach it: Return presses the first submit button of the field’s own form.

04

Usage

  1. Do

    Ask one question in the title and answer it with verbs: “Delete Shapes?” with Delete deck and Keep it. Say what goes with it. Make the safe choice primary, last and focused.

  2. Don’t

    Don’t ask “Are you sure?” or label the buttons Yes and No. Don’t make the destructive button primary or red. Don’t stop anyone for news that needs no answer (a toast or a banner says it), and prefer Undo to a question when the action can be undone.

  3. Installed PWA

    Centred on a phone too. The buttons share a row when both labels fit (most phones at default text) and stack full width with the primary on top on a 320pt phone or at larger text. A phone has no Escape key, so every dialog has a button that closes it. It fades and settles in, and fades out; with Reduce Motion on, it only fades.

  4. Mac and SwiftUI

    Alerts are system chrome: SwiftUI’s .alert or .confirmationDialog, with Button(role: .destructive) and a cancel button. This element is the web shell’s. Return presses the focused button; Escape cancels.
