Field

Lets someone type one value. A square frame, because it holds text; a label that never goes away; and an error that says how to fix it, without needing colour.

01

Anatomy

Six parts. Only the label and the input are always there. Help and error sit between them, above the input, where the on-screen keyboard can't cover them.

Shown on the deck's card.

Give the deck a name

5 6
  1. 1
    Label.field__label

    A real <label for>, above the input, always visible. 16px, weight 600, sentence case. Never replaced by the placeholder.

  2. 2
    Help.field__help

    14px, soft ink. Tied to the input with aria-describedby.

  3. 3
    Error.field__error

    A warning glyph and the fix, in words: 16px, weight 600. Listed first in aria-describedby; the input gets aria-invalid="true".

  4. 4
    Input.field__input

    A 2px square frame, 44px tall, 16px text. Wrapped in .field__box only when an icon or a clear button sits in it. Invalid doubles the frame.

  5. 5
    Leading icon.field__icon

    Decorative and aria-hidden. Clicks go through it to the input.

  6. 6
    Clear button.field__clear

    A real <button> with aria-label="Clear search": a 44px target around a 28px circle. Round, because it acts.

02

Variants

Four, and they share everything but the input: the same frame, label, help and error. Each one asks the phone for the right keyboard and the right Return key.

2.1

Text

One short line: a name, a title.

.field .field__label .field__help .field__input

type="text", autocomplete="off" (a deck name isn't personal data, so no browser suggestions), enterkeyhint="done", or "next" when another field follows.

Shown on the deck's card. You can change it later.

2.2

Search

Narrows a list as you type.

.field__box .field__icon .field__clear

type="search" inside <search>, enterkeyhint="search", autocomplete="off", autocapitalize="none". The clear button shows only while there's text: the app toggles hidden, empties the field and puts focus back in it. Escape clears too, natively. The placeholder is an example, not the label.

2.3

Number

A count you'd rather type than step to.

.field--number

type="text" with inputmode="numeric" and pattern="[0-9]*": the number pad, no spinner arrows, and no scroll wheel changing the value by accident. Its width hints at the answer. The range goes in the help, and the check happens on submit.

From 5 to 50.

2.4

Multi-line

A few sentences.

textarea.field__input

A <textarea>, four rows to start. It resizes downwards only and keeps its scroll to itself. enterkeyhint="enter", because Return makes a new line here.

Only you see these.

States

Seven states, all from the input itself. A field isn't pressed, so it never lifts: hover changes its ground, focus rings it. Grey only, so every state has to read without colour.

The .is-* classes force a state for this page and for tests. They are not API: real states come from :hover (only where a pointer hovers), :focus-visible, :active, aria-invalid, disabled and readonly.

04

Usage

  1. Do

    Name the thing in the label ("Deck name", not "Name"). Put the range or the rule in the help. Write the error as the fix: "Give the deck a name", not "Required".

  2. Don't

    Don't use the placeholder as the label: it vanishes on the first letter. Don't disable a field without saying why next to it; read-only, or leaving it out, is usually kinder.

  3. Installed PWA

    16px text or more, or iOS zooms on focus. inputmode and enterkeyhint pick the keyboard and its Return key. Help and error sit above the input, so the keyboard never hides them.

  4. Mac and SwiftUI

    The toolbar's search is the system's own field (.searchable); ours are for content. In SwiftUI, a TextField with a custom style: a 2pt square stroke, our label above, the system focus ring.
