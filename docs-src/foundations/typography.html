Typography

One family, three widths, six styles. Archivo's width axis does the job a second typeface normally does: expanded for posters, normal for reading, condensed for labels. Everything is in rem, so it follows the size the reader chose.

Archivo Variable

--font-sans is "Archivo", "Helvetica Neue", Helvetica, Arial, sans-serif. One self-hosted file, src/fonts/archivo-latin-var.woff2, is variable on both axes: weight 100 to 900 and width 62% to 125%. It is declared in 50-fonts.css with font-display: swap, so text shows immediately in the fallback and swaps when the font arrives. Licence: SIL OFL 1.1 (src/fonts/OFL-Archivo.txt).

  • Why self-hosted. No third-party request on first load, it works offline in an installed PWA, and from file://. Copy the fonts/ folder next to styleguide.css; the @font-face points at fonts/archivo-latin-var.woff2.
  • Latin subset. It includes the true minus (U+2212), the euro sign and the tabular figures. It does not include check marks, left and right arrows, or the signs for at most, at least and approximately. Draw those as icons; npm run lint warns on the glyphs it knows are missing. For another script, add its subset as a second @font-face with its own unicode-range.
  • --font-mono is the system monospace stack, for code in docs and apps. It is the only other family, and it never appears in the product UI.

Three widths

Width is a font property, set with font-stretch (the font shorthand takes the keywords). The type styles use four of the values the axis offers:

  • Streak 12condensed (75%): --type-label. Uppercase labels.
  • Streak 12normal (100%): title, body, meta, control. Everything you read.
  • Streak 12semi-expanded (112.5%): --type-figure. Big numbers.
  • Streak 12expanded (125%): --type-display. The poster line.

Try the axes. The sample is one element with font-weight and font-stretch set from the sliders.

The size scale

Eight steps, all in rem. The first four are fixed; --text-xl and up are clamp() ranges that follow the viewport, so a page title is smaller on a phone and larger on a desk without a media query. The last column is the computed size at this window width.

Two more rules keep the scale honest. Sizes are never written in px (lint fails it), and the root is never resized: no html { font-size: … }. The reader's setting is the scale.

Inside a card, the card's width decides

A card can sit in a one-column phone layout or a four-column desk grid, and the viewport cannot tell which. So type inside a card is sized from the card's own width with cqi (1% of the container's inline size): .card__title is clamp(1.375rem, 8cqi, 2rem), .card__figure is clamp(3rem, 27cqi, 6.5rem), .card__hero is clamp(2.25rem, 17cqi, 3.75rem), and the card's padding clamp(1rem, 5cqi, 1.5rem). Never put cqi on the container itself

A container's own cqi resolves against its container, not itself. That is why .card never sizes itself in cqi, and why sizes that use it live on the parts (.card__body, .card__title). The card's --card-pad holds a cqi value and is safe: a custom property is substituted where it is used, so it resolves on the part.

Numerals

Money, time and counters use tabular figures, so columns line up and a ticking number does not jitter. .num does it (font-variant-numeric: tabular-nums lining-nums), and .t-meta and .t-figure already include it. Archivo's default figures are proportional: in the first column below a 1 is narrower than an 8.

Format with Intl, and use the true minus

Format numbers, dates and currency with Intl, never by hand, and never hard-code a separator. Intl.NumberFormat in most locales returns a hyphen-minus, which is a dash; a negative amount should use the true minus, U+2212 (−), which the font has and which is as wide as the plus. The table is computed in your browser.

const money = (n, locale = 'en-US', currency = 'USD') =>
  new Intl.NumberFormat(locale, { style: 'currency', currency }).format(n).replace('-', '−');

Case and tracking are CSS

Uppercase is structure: the display line, bar labels, index numbers. Everything you read is sentence case. Write the natural case in the HTML and let text-transform do the rest: .t-display and .t-label uppercase themselves. Typed capitals get copied as shouting, read as the translator saw them, and ignore the language: text-transform knows that Turkish i becomes İ.

Do

<p class="t-label">Weekly goal</p>

Weekly goal

Don't

<p>WEEKLY GOAL</p>, or an uppercase sentence.

Tracking follows size and case: labels are tracked out (+0.08em) so small capitals breathe; the display line and the big figure are tightened (−0.035em, −0.03em) because letter gaps grow with the type. Those values live in --ls-display, --ls-title, --ls-figure and --ls-label.

Wrapping, line length and long words

  • Titles balance, body text is pretty-wrapped. .t-title and the h1 to h3 defaults use text-wrap: balance; .t-body uses pretty, which avoids a last line of one word.
  • Long words wrap. The reset gives headings, paragraphs and list items overflow-wrap: break-word. In a flex or grid row the item's minimum width is still the whole word, so a long word is clipped or overflows (first box below). Add .break (overflow-wrap: anywhere with hyphenation). .card__hero already does.
  • Truncate on purpose only. .truncate is one line with an ellipsis, .clamp-2 is two lines. Anything truncated needs its full text available somewhere else.
  • Measure. --measure is 62ch, the widest a paragraph gets; .prose applies it and spaces its children. .card__text stops at 40ch.

Text size scaling

  • Every size, line height and spacing that depends on text is in rem. Browser text size, browser zoom and (on Android) font scale all work, and layouts are tested with text at 200% and width at 320px by npm run test:a11y.
  • On iOS, base asks for Dynamic Type through font: -apple-system-body behind @supports, and pins desktop Safari back to 100%. That is unverified on a device. If it misbehaves in your app, delete the two @supports blocks in src/base/10-base.css; everything is still in rem.
  • Controls grow with their text: heights are min-block-size in rem, and labels wrap instead of clipping.

Change the typeface

The typeface is one token and one @font-face. Add the new face's file and @font-face to src/tokens/50-fonts.css and point --font-sans at it in 00-foundation.css; nothing in a component names a family. Three things to know: npm run lint rejects a default as the first family (Inter, Roboto, Arial, system-ui and a short list of others: "a default, not a choice") and any font-family that is not a token; a face without a width axis ignores expanded and condensed, so the display, label and figure styles lose the width they depend on and need their tokens reworked; and the glyphs you need (true minus, tabular figures) must be in the new subset.

Do and don't

Do

Reach for a style first: font: var(--type-title) or .t-title. Use .num on anything that counts or adds up. Size with rem and cqi.

Don't

Add a second family, write a size in px, resize the root, type capitals, or draw a check mark or arrow with a text glyph the font does not have.
