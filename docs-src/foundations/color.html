Colour

Every colour in the guide is chosen by lightness first and hue second. Lightness is what WCAG contrast measures, so each pair of roles keeps a fixed lightness gap and cannot drop below its floor, whatever palette, theme or contrast setting is active.

Open Appearance (top right) while you read. Every swatch, ratio and demo on this page is read from the real tokens, and recomputes when you change theme, palette or contrast.

Knobs, roles, components

Colour is built in three steps. Each step reads only the one before it, which is why a palette can change every colour in a product without touching a component.

Step 1

Knobs

Plain numbers: OKLCH lightness, chroma and hue, named --k-*. A -l or -d suffix means the light or the dark theme. Palettes, the contrast mode and the theme change knobs and nothing else.

Step 2

Roles

Colours with a job: --ink, --paper, --accent. Each is one light-dark(oklch(…), oklch(…)) built from knobs.

Step 3

Components

Read roles and nothing else. No hex, no oklch(), no opacity on text. A component never knows which palette, theme or contrast mode is active.

One role through all three steps (from src/tokens/10-color.css):

/* 1 · knobs: plain numbers */
--k-ink-l: 0.2;   --k-ink-d: 0.96;
--k-neutral-c: 0; --k-neutral-h: 95;

/* 2 · role: derived, declared on :root, [data-theme], [data-palette], [data-contrast] */
--ink: light-dark(
  oklch(var(--k-ink-l) var(--k-neutral-c) var(--k-neutral-h)),
  oklch(var(--k-ink-d) var(--k-neutral-c) var(--k-neutral-h))
);

/* 3 · component */
.card__title { color: var(--ink); }

Why roles are declared again on every scope

A custom property whose value contains var() is resolved on the element where it is declared. A nested <section data-palette="mint"> therefore needs its own copy of every role, computed from its own knobs; otherwise it would inherit the parent's finished colours. That is why the role block in 10-color.css lists :root, [data-theme], [data-palette], [data-contrast]. The palette islands further down are the proof.

Contrast by construction

WCAG contrast is a ratio of relative luminance, (Y1 + 0.05) / (Y2 + 0.05). For neutral colours OKLCH lightness L is close to the cube root of luminance, so Y is roughly L cubed. That turns contrast into a lightness gap you can reason about, and it holds whatever the hue, because hue and chroma barely move luminance at the low chroma the neutrals use.

Accent

The accent is the one "press this" colour: the primary button, the thing you are pointing at. In the default palette it is ink (black on light, white on dark); the other palettes give it a hue.

Overlays and media

Text or an icon over a photo, video or map never goes straight on the image. A scrim gives it a known background. --scrim is black at 60% and --scrim-strong at 75%; --on-media is white. The scrim is the one translucency the guide allows, and it is also the modal backdrop.

Tone pairs have their own table on Tones. Three things to know when reading this one:

  • --ink-soft and --ink-mute measure lowest on --paper-3. On the canvas, a card and --paper-2, --ink-soft is over 7:1 in both themes; put secondary text on a pressed shade and expect the lower number.
  • --accent against the canvas is not a rule. A pale accent (cream's yellow) is only about 1.3:1 against a cream canvas, so the fill never works alone: every filled control keeps its 2px --line frame, and "on" adds a second cue.
  • Ratios come from 8-bit sRGB pixels as painted by Chromium. A display with a colour profile can differ a little. Nothing here is verified in Safari or Firefox.

Dark

Dark is not a second design. It is the same roles with the second half of each light-dark() value, so every rule above holds in both. The theme follows the operating system unless the app sets data-theme="light" or data-theme="dark" on <html>, or on any element to make an island (an island paints its own --canvas and --ink, or it would show the parent's page behind it).

  • Depth stays lightness. The canvas is 0.165 and a card is 0.22, then 0.27 and 0.32 for recessed and pressed. Cards are lighter than the page in both themes, and there is no shadow to lean on.
  • No pure black, no pure white. Ink is 0.96, not 1, and the page is 0.165, not 0. Less glare, and halation on OLED stays low.
  • Tones mirror. A pastel tone is light at 0.93 with dark text in the light theme and dark at 0.27 with light text in the dark theme (see Tones). A bold tone is the same in both.
  • The default accent swaps. Black with a white label in light, white with a dark label in dark, which is why the accent is a role and never a colour you write.
  • The browser chrome follows. SG.prefs keeps <meta name="theme-color"> in step with --canvas when the user overrides the OS theme.

Higher contrast

Higher contrast is a further tier of the same palette, not a second design. It turns on when the operating system asks for more contrast (prefers-contrast: more) or when the app sets data-contrast="more" on <html>. It changes knobs only, so every palette, tone and status inherits it.

Two rules keep the tier trustworthy. First, the OS query block and the data-contrast="more" block in each token file are copies of each other, and tests/lint.mjs fails if they differ. Second, tests/contrast.mjs renders each palette with the media query and with the attribute and fails if any role differs. data-contrast="off" is honoured by the CSS (it ignores the OS request), but SG.prefs and the Appearance panel only offer System and More.

Higher contrast reaches islands

A region can ask for more contrast with <div data-contrast="more"> on a normal page (measured: --k-ink-l goes from 0.2 to 0.1 inside it), and a palette island inside a higher-contrast page gets the boost as well, because the knob block is repeated for [data-palette]. tests/contrast.mjs checks both cases. Motion is the exception: data-motion works on <html> only.

Why text never uses opacity

A faded colour is a guess about what is behind it. opacity and alpha colours blend with whatever is underneath, so the ratio depends on the surface, the theme and the palette, and it changes the moment the text moves onto a toned card. A role is a fixed colour with a tested ratio on a known set of surfaces.

Don't: color: var(--ink); opacity: 0.6. Measured: n/a
  • Opacity also stacks: a faded child inside a faded parent is lighter than either alone would suggest.
  • Browsers dim ::placeholder on their own. The base layer resets it to opacity: 1 and colours it --ink-mute, so it still measures 4.5:1.
  • Disabled text is exempt from WCAG contrast, but the guide still uses --ink-faint and a dashed frame, so it stays legible and says "not here" twice.

Islands layer on the page; they do not reset it

A palette block starts from the default knobs and changes only what it lists, so an island looks the same as a page with that palette, whatever palette the page has: a mint island inside a wire page is mint, and a data-palette="default" island inside a mint page is the default. npm run test:contrast compares every island with a page of the same palette. Corner style layers the other way: an island on a soft page has soft corners unless it sets data-corners="square", which the islands here do. Use island palettes for a region that differs from the page.

Make your own palette

  1. Open src/tokens/40-palettes.css and copy the block closest to what you want: mint for a coloured accent, cream for a pale one, sand for a tinted neutral with an ink accent.
  2. Rename the selector to [data-palette="yourname"].
  3. Set the hue knobs: --k-neutral-h and --k-neutral-c tint every neutral; --k-canvas-c-l and --k-canvas-c-d tint the canvas more than the rest; --k-accent-h and --k-accent-c colour the accent; --tone-h-1 and --tone-c-1 (up to 6) point the six tone slots at hues.
  4. Keep the accent lightness knobs inside the shared group at the top of that file (fill 0.48 / 0.76, label 0.99 / 0.18, accent text 0.45 / 0.82). Contrast was designed around those values. If your accent is pale, follow the next section instead.
  5. Add the name to PALETTES in tests/contrast.mjs and to OPTIONS.palette in docs-src/assets/docs.js so the Appearance panel offers it.
  6. Run npm run test:contrast. Fix the knob that fails, not the component that shows it.

      Rules for light accents

      Cream's yellow is a pale accent. Three things follow from that, and all three are set in the cream block of 40-palettes.css. Copy them whenever an accent fill is lighter than about 0.75.

      1. The label is dark. --k-on-accent-l and -d are 0.2, so text on the yellow is well over 7:1. White on a pale fill would fail.
      2. Accent text is a dark shade of the hue. --k-accent-ink-l is 0.42 (light) and 0.88 (dark), so accent-coloured text reads on the canvas. A pale fill cannot be used as text.
      3. The frame carries the shape. A pale accent is only about 1.3:1 against a cream canvas, so the fill alone cannot show a pressed or selected control (WCAG 1.4.11). Every pressable thing already has a 2px --line frame, and "on" adds a doubled frame, so nothing depends on the fill.

      Do
