Interaction

Everything you can press has two numbers. --lift says how raised it is; --fill says how filled it is. Every state, hover, focus, pressed, on, disabled, only sets those two numbers, and one transition animates them. A hard shadow means "you can press this", and nothing else gets one.

Two numbers

The two interaction numbers
PropertyIs01
--liftGeometryFlat, on the pageRaised: moved 2px up and left, with a 4px hard shadow
--fillColourOutline: the resting coloursFilled: the accent (or the tone's fill)

Both are registered in 00-foundation.css as @property numbers, initial value 0, and they inherit. Registered matters: a transition can only interpolate a custom property if the browser knows its type; an unregistered one would flip instantly. Inherit matters because the parts of a pressable follow it: the arrow in a link card fills when the card does.

A pressable derives everything from them. This is the heart of src/components/button.css:

.btn {
  --lift: 0;
  --fill: 0;
  --_shadow: calc(var(--lift) * var(--space-1)) calc(var(--lift) * var(--space-1)) 0 0 var(--line);

  color: color-mix(in srgb, var(--_on-ink) calc(var(--fill) * 100%), var(--_rest-ink));
  background: color-mix(in srgb, var(--_on-bg) calc(var(--fill) * 100%), var(--_rest-bg));
  box-shadow: var(--_select), var(--_shadow);
  transform: translate(
    calc(var(--lift) * var(--space-1) / -2 * var(--move)),
    calc(var(--lift) * var(--space-1) / -2 * var(--move))
  );
  transition:
    --lift var(--dur-hover) var(--ease-out),
    --fill var(--dur-hover) var(--ease-out);
}

Drive the numbers yourself. Setting them inline overrides the states, which is exactly what a state does: sets them. Reset returns control to hover, focus and press.

Why the buttons above are in Mint

In the default palette the accent is ink, so a filled button, its hard shadow and the second ring of "on" are all the same black and read as one lumpy shape. The offset is still there, but fill, frame and shadow cannot be told apart. In any palette with a colour accent they separate cleanly, so the specimens on this page use Mint for that reason. It is also why "on" needs a cue that is not colour: a check icon, as in the Selected section.

The hard shadow

A shadow means "you can press this". It is hard-edged (zero blur), drawn in --line, and sized by the number: --lift times --space-1 across and down. Raised also moves the element half that distance up and left, so it looks lifted off the page rather than stuck to a shadow. The page has no other shadow; the one exception is the --scrim behind a modal or under text on a photo.

Stat

Five known

Holds something. Flat, always.

Does something. Raised when it can be pressed.

Do

Let the state set --lift and --fill and nothing else. The shadow, the move and the colour all follow.

Don't

Put a shadow on a card "for depth", write a blur, or hand-set box-shadow in a hover rule. A shadow on something you cannot press is a lie, and lint fails any blurred one.

Selected and on

"On" is filled and the frame doubles: a second ring of --bw drawn with box-shadow: 0 0 0 var(--bw) var(--line). The second cue is what makes it survive a pale accent (cream's yellow is 1.3:1 against its canvas), greyscale, and forced colours. A ring, not a wider border, so nothing shifts when it turns on. Add a check icon or a heavier weight when the meaning needs saying twice.

Selection is ARIA, never a class: aria-pressed for a toggle, aria-selected for a choice in a listbox, tab list or grid, aria-current for where you are. The card above uses aria-current; the card styles either. CSS that styles a state the screen reader was not told about is a bug.

Unavailable

Dashed means "not here". A disabled control has a dashed frame, --ink-faint for its text and frame (never opacity), no shadow, no hover, and a not-allowed cursor. Prefer aria-disabled="true" with a reason in aria-describedby to the disabled attribute: it stays in the tab order, so a keyboard or screen-reader user can land on it and find out why. aria-disabled does nothing on its own, so src/js/20-guard.js makes it inert for click, Enter and Space, in the capture phase, for every button, link and role="button".

Busy

aria-busy="true" adds a spinner before the label (var(--anim-spin), which becomes a slow pulse under reduced motion), ignores taps and shows a progress cursor. Nothing tells a screen reader that work has finished, so announce the result with SG.announce().

Focus

The ring is outline: var(--ring) solid var(--focus) with outline-offset: var(--ring-gap, var(--ring-offset)): 3px wide, 3px out. On every link, button, input and other interactive element it comes with a --paper halo (--focus-shadow) that fills the gap, so the ring still shows where --focus (which is ink) would vanish: on an ink bar, in a dock, on a dark photo. Keyboard focus also raises the control (lift 1, fill 1), exactly as hover does.

  • A component that draws its own shadow keeps the halo: box-shadow: var(--focus-shadow), <own>. Button does.
  • Inside something that clips (a card), use the inner offset: --ring-gap: var(--ring-offset-in) (2px). Do not put overflow: hidden between a focusable element and its ring.
  • On an ink surface the ring follows the surface. An ink ring on an ink card vanishes, so the card recolours it to paper (.card[data-tone="ink"] :focus-visible) and the bar recolours it to the bar's text colour.
  • Sticky chrome never hides it. App bars and docks set --appbar-h and --dock-h; html turns them into scroll-padding-block (WCAG 2.4.11).

Touch, pointer and time

  • Hover is gated with @media (hover: hover), everywhere. Lint warns on an ungated :hover. On a touchscreen a tap would otherwise leave the control raised until the next tap.
  • Press feedback is immediate. :active switches the transition to --dur-press (130ms), and the filled colour starts changing on the first frame. html sets -webkit-tap-highlight-color: transparent, which is only safe because every control has a pressed state.
  • No double-tap delay. Links, buttons, inputs and labels get touch-action: manipulation.
  • Gestures are an enhancement. Swipe, drag and reorder each need a tap or key equivalent (WCAG 2.5.7); every state above is reachable with Tab, Enter and Space.
  • Reduced motion removes the travel, not the change. --move multiplies the translate, so at 0 the control does not move; the fill, the shadow and the frame still change. See Motion.

Forced colours

In Windows contrast themes (forced-colors: active) the browser replaces your colours with the reader's palette and deletes backgrounds and shadows. Everything that leaned on a fill or a shadow to show a state is gone, so the structure has to live in lines.

  • A real border on every control and card, even one that is transparent. The component sets it to ButtonText or CanvasText.
  • Hover, focus and selected become heavy lines. Raised and focus get an outline: var(--bw-heavy) solid Highlight; "on" gets border-width: var(--bw-heavy); disabled is GrayText. The base focus ring becomes a 4px Highlight outline with box-shadow: none.
  • Icons are backgrounds (masks), so .ic opts out with forced-color-adjust: none and paints with CanvasText; otherwise every glyph would vanish.
@media (forced-colors: active) {
  .btn {
    border-color: ButtonText;
    &:is(:hover, .is-hover, :focus-visible, .is-focus) {
      outline: var(--bw-heavy) solid Highlight;
      outline-offset: 0;
    }
    &[aria-pressed="true"] { border-width: var(--bw-heavy); }
    &:disabled, &[aria-disabled="true"] { color: GrayText; border-color: GrayText; }
  }
}

The accessibility gate runs every page once in forced colours and fails if a control has no visible border. To look yourself: Chromium DevTools, Rendering, Emulate CSS media feature forced-colors, or a Windows contrast theme. This has not been verified on a real Windows machine.

Make a new pressable

  1. Copy the structure of src/components/button.css. Declare --lift: 0; --fill: 0; on the element.
  2. Keep what varies in private properties (--_rest-bg, --_on-bg, --_select); the base rule consumes them.
  3. Build colour from --fill with color-mix(), the shadow and the translate from --lift, and multiply the translate by --move.
  4. Write each state as a rule that sets --lift and --fill and nothing else: hover (gated), :focus-visible, :active, and the ARIA states.
  5. One transition for both numbers. No transition: all.
  6. Give it a real border, a 44px hit area (the ::after pattern), box-shadow: var(--focus-shadow), … on focus, and a forced-colours block.
  7. Write the spec. tests/components/button.mjs reads --lift and --fill at rest, on hover, while the mouse is down and on keyboard focus, and asserts 0/0, 1/1, 0/1 and 1 again.
