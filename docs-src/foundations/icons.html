Icons

Every symbol is a CSS mask drawn on a 24 grid with a 2px square-cap stroke, the same weight as a frame, so an icon reads as part of the line work and not as a sticker. It takes the text colour, scales with the text, and works from file://.

Using one

<span class="ic ic--plus" aria-hidden="true"></span>

.ic is an inline box the size of --ic-size (1.25rem by default) filled with currentColor and cut to shape by a mask, mask: var(--ic) center / contain no-repeat. The glyph itself is a custom property, which is why one class per icon is all it takes: .ic--plus sets --ic.

Rules

  1. Symbols are icons. Never a text arrow, tick or bullet, an emoji, or an icon font. The bundled font has no check marks, no left or right arrows and none of the signs for at most, at least or approximately; emoji draw differently on every device; icon fonts vanish in forced-colours mode. Lint warns on the text glyphs it knows about.
  2. Hide decoration, name controls. Every icon gets aria-hidden="true". The control that contains it carries the name.
  3. Colour is currentColor. An icon takes the text colour of its parent, so it follows the theme, the tone and the palette.
  4. The glyph is not the target. A 20px icon sits inside a 44px control (the .btn circle, the .card__ctl slot); do not pad an icon to make it tappable.
  5. One icon, one meaning. Use the same icon for the same job everywhere in an app.

The docs lint fails any <button> with neither text nor an aria-label, and the build fails on an icon class that does not exist.

Size, weight and colour

Set --ic-size on the icon or on any parent. It is rem, so icons grow with the reader's text size. The drawing is a 2-unit stroke on a 24-unit grid, so the line is exactly 2px at 24px and scales with the icon: about 1.7px at the default 20px, 1px at 12px. That is the one place icons and frames differ; it is a consequence of scaling a drawing, and it is why the smallest icon in the guide (the 12px glyph inside a card's control) sits in a 20px box.

  • 0.75rem · 12
  • 1rem · 16
  • default · 20
  • 1.5rem · 24
  • 2rem · 32

Colour. Icons follow color. Use a text role and keep meaningful icons at 3:1 or more (WCAG 1.4.11). In a status the icon is paired with words, and the colour is a third cue.

Add an icon

  1. Find it on lucide.dev/icons and save its SVG. Use Lucide's current name: several were renamed.
  2. Save it as src/icons/<id>.svg. The file name is the id: lowercase, hyphenated. It must have viewBox="0 0 24 24"; the build fails otherwise. Only the inner shapes are used. Their stroke, caps and joins are replaced by the guide's (2px, square, mitred), so the source file's own stroke and width attributes are ignored.
  3. Run npm run build. The icon is in dist/icons.css, in the gallery below, and usable as ic--<id>.
  4. Keep src/icons/LICENSE-lucide.txt next to the files.

An icon you draw yourself follows the same rules: stroke-only shapes on the 24 grid that still read at 2px with square ends, no fills, no colours, and a couple of units of padding inside the box. Check it at 16px, the smallest size it will be used at.

Limits

  • One colour. A mask has a single colour. There are no duotone or multi-colour icons.
  • One weight. A single stroke style, and no animated icons: a spinner is a CSS ring (see Motion).
  • No automatic mirroring for right-to-left. An arrow or chevron points the same way in every direction. For RTL, pick the opposite icon or flip it in a [dir="rtl"] rule.
  • A mask is not an image. There is no alt; naming is the control's job, as above.
  • Only the icons in the gallery. Add what you need as above.

Do and don't

Do

Pair an icon with a word wherever there is room. Name icon-only controls with aria-label, and let the icon take the text colour.

Don't

Use an emoji or a text arrow, rely on an icon alone to say "saved" or "failed", put an icon in a tinted circle for decoration, or give two different icons the same job.

Tokens used

--ic-size, --ic, --icon-arrow, --icon-plus, --icon-minus, --icon-close, --icon-check, --hit. Classes: .ic, .ic--<id>.
