Checkbox and radio

Checkboxes let people pick any number of options; radios make them pick exactly one. Both are real inputs, so grouping, arrow keys and form submission come from the browser. The box is a square because a rectangle holds; the radio is a circle because circles act. Both lift on hover.

When to use

Do

Use radios for two to five mutually exclusive options that should all be visible. Use checkboxes for independent yes / no choices and for "select several". Always group related choices with a fieldset and legend.

Don't

Use a checkbox for something that takes effect immediately (use a switch), or a radio group with one option. Don't preselect a consent checkbox.

Examples

Checkbox

The whole row is the target: the input itself is a transparent 44 px square, the box is drawn on it, and the label is clickable too. The mark is a mask of the icon set's own tick, never a text glyph. Hover, tab in, or press to see the box lift and sink.

Radio group

Wrap the options in a <fieldset> with a <legend>: the legend is read with every option. Radios share a name, so there is one tab stop for the group and the arrow keys move and select.

Indeterminate: "some of them"

A parent checkbox that stands for a group of children shows a dash when only some are checked. Indeterminate is a property, set in script (input.indeterminate = true); CSS reads it with :indeterminate and assistive technology hears "mixed". Put the children in a .choice-group inside the parent's group: it indents them to sit under the parent's label.

Notifications

Choice cards

Use when each option needs more than a word: a top-up method, a plan, an account type. It is a card you can select: the card supplies the frame, the parts and the tones, the input stretches over it, and the corner mark says what kind of choice it is (a circle for one-of, a square for any-of). Selected = the frame doubles and the mark fills with a tick. The whole card is the hit area and wears the ring. Do not put links or buttons inside one.

Extras

Segmented

Native radios drawn as one pill track, for picking a value or a filter from two to four short options: "Bank account | Transactions", "Day | Week | Month". The selected segment is a filled pill with its own frame inside the track's frame, so it has two outlines and inverted text and never relies on the accent. The track wears the focus ring: arrow keys move focus and the selection together. If choosing swaps a whole panel of content, use tabs instead.

Anatomy

  1. Row (.choice, a <label>): at least 44 px tall; clicking anywhere on it toggles the input. It carries --lift.
  2. Input: the real <input>, 44×44 px and transparent, so it is the measured target.
  3. Box (input::before): 24 px, --bw frame in --line; a square at --radius-ctl for checkboxes, a circle for radios. Filled with --accent when on (--fill); raised by --lift with the hard shadow.
  4. Mark (input::after): a tick, a dash or a dot, in --on-accent. It fades with the fill.
  5. Label (.choice__label): 16 px, optionally with a .choice__hint.
  6. Group (fieldset + legend, then .choice-group): 8 px between rows.
  7. Card (.card.choice-card): the input covers the card; the mark sits in the top corner at the end side.
  8. Segmented (.choice-group[data-variant="segmented"]): a pill track with the ring on it; segments are the labels.

Accessibility

Checkbox and radio keyboard and screen reader behaviour
InteractionBehaviour
TabCheckboxes: one stop each. Radios: one stop for the whole group (the checked one, or the first).
SpaceToggles a checkbox; checks a radio.
↑ ↓ ← →Radios (including cards and segments): move focus and select the previous / next option, wrapping. Native.
Screen reader"Remind me about my streak, check box, not checked". Radios add the legend and position: "Session length, group. Standard 20 cards, about 8 minutes, radio button, 2 of 3". A hint inside the label is part of the name; for a long one, give it an id and point the input at it with aria-describedby instead. Indeterminate is "mixed".
Touch44×44 px input and a full-width label, 8 px between rows. Segments reach 44 px tall and sit 4 px apart in their track (one control, not separate buttons).
Not colour aloneChecked = filled box and a tick / dot. Card selected = doubled frame and a tick. Segment selected = a second outline and inverted text. Invalid = inner second frame.
FocusThe ring wraps the drawn box, the whole card, or the whole segmented track.
Reduced motionNo lift travel; the fill and the mark still fade.
Forced coloursThe box and mark are redrawn with system colours (Canvas, CanvasText, Highlight), so checked still reads as a filled box with a tick; selected cards and segments get a 4px frame.
