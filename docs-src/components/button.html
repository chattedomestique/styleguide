Button

A button does something on this screen: save, add, send, confirm. If it goes somewhere else, it is a link.

When to use

Do

One primary button per screen or card. Label it with the verb and the thing: Save task, not OK.

Don't

Use a button for navigation (use <a href>), or put two primary buttons side by side.

Examples

Variants

Primary is the single most important action. The others step down in emphasis.

Tone

Inside a tonal card the button takes the card's hue and stays readable by construction. See Tones.

Sizes

Every size has a 44 px hit area, even the 40 px small one, which extends its tappable area invisibly.

With an icon

Icon buttons: the circle family

Three treatments, each with one meaning: solid is the primary action, surface is secondary, outline is tertiary. Scrim is for controls that float over photos and video. An icon button always needs an aria-label.

States

States come from ARIA and native attributes, so the look cannot disagree with what a screen reader is told. Tab to each one and press it.

Anatomy

  1. Container: fill, border, radius, hard shadow (pop only). Always has a border, transparent on filled variants, so forced-colours mode still shows an edge.
  2. Label: verb first, 1–3 words. Semibold, never below 14 px. Case comes from the surface style, never from the HTML.
  3. Icon (optional): 20 px, decorative (aria-hidden) when a label is present.
  4. Hit area: an invisible extension that guarantees 44×44 px.

Accessibility

Button keyboard and screen reader behaviour
InteractionBehaviour
Tab / Shift+TabMoves focus to and from the button. The two-tone focus ring is visible on every background.
Enter or SpaceActivates. Native <button> gives this for free; never use a <div>.
Screen readerAnnounced as "Label, button". Toggles add "pressed"/"not pressed"; busy adds "busy"; aria-disabled adds "dimmed/unavailable".
Touch44×44 px minimum hit area, 8 px minimum gap to neighbours. No gesture required.
Zoom / text sizeHeight and padding are in rem and grow with text; labels wrap rather than clip. Nothing is fixed in px.
Reduced motionNo shrink on press, spinner becomes a pulse. The colour change stays.
Forced coloursBorders become system colours; toggled buttons gain a thicker border because fills are removed.
  • Text contrast is verified for every variant in every theme and palette by npm run test:contrast (≥ 4.5:1).
  • An icon-only button needs a text name. A tooltip alone is not a name.
  • Never signal state by colour alone: pressed changes fill and border weight, busy adds a spinner, disabled changes fill and text colour and the cursor.
