Menu

A menu is a short list of commands behind one button: Rename, Duplicate, Sort by, Delete. It follows the WAI-ARIA menu button pattern on the native popover attribute, so it layers above everything, closes when you click away and needs no z-index. Rows are ruled, edge to edge, and invert as you move through them.

When to use

Do

Use a menu for actions and a few settings on one object, when there is not room for a button each. Put the most common first, separate destructive commands and end the list with them. A destructive row is always an icon and a word.

Don't

Use role="menu" for site navigation (that is a list of links), for choosing a value in a form (a select or a radio group), or to hide the only way to do something important. Do not nest menus: on a phone they cannot be used.

Actions

The basic menu. Enter, Space or ArrowDown on the button opens it and focuses the first row; ArrowUp opens on the last. Delete sits last, after a rule, with its icon. Archive is unavailable: it stays in the list, dashed, and says why.

Icon-only button, aligned to the end

A "more" button at the end of a row. It has no visible text, so it needs an aria-label naming the thing it acts on; a tooltip is not a name. data-placement="bottom-end" lines the menu's end edge up with the button so it stays on screen.

Checkable rows

menuitemradio picks one of a group, menuitemcheckbox toggles one setting. SG flips aria-checked; the check icon and the heavier label show it, so it never depends on colour. Radios choose and close. Checkboxes can stay open with data-keep-open so several can be changed in one visit. Groups are named by a .menu__label.

Action sheet (phones)

data-presentation="sheet" shows the same menu docked to the bottom edge: full-width rows 56px tall, a scrim and a Cancel row, because a phone thumb cannot hit a small dropdown and a touch screen has no Esc. data-presentation="auto" does this below 40em and leaves a dropdown above, so one menu serves both: the second button below, Export deck, is an action sheet on a phone and a dropdown on a wide screen. A command that needs a decision

A menu row can open a dialog. The row is hidden the moment the menu closes, so when the dialog closes focus goes back to the menu's button, not to nowhere.

Row states, square and soft

Static previews (data-inline) with every state forced by the docs-only is-* classes: rest, hover, keyboard focus (filled and ringed inside the row), pressed, checked, unavailable (dashed, with its reason) and destructive. The same markup in both corner styles; the frame is --radius-tile. A menu highlights the row under the pointer with the full fill on purpose: it is a list of commands, not a set of choices, and only one row is ever highlighted; checked is told by the check and the weight.

Anatomy

  1. Button: any .btn with aria-haspopup="menu", aria-expanded, aria-controls and popovertarget. An icon-only button carries an aria-label. An optional .menu__chevron turns over while open.
  2. Menu: <div class="menu" popover role="menu" aria-labelledby="button-id">. A framed list below the button (above if there is no room), at least as wide as the button, 12rem at the least. No shadow.
  3. Row (.menu__item): a real <button> (or link) with a menuitem* role, 44px tall, icon then label, optional .menu__meta. Rows are separated by a 1px rule and invert with --fill.
  4. Check (.menu__check): the leading icon of a checkable row, visible only while checked.
  5. Group and rule: role="group" named by a .menu__label, and <hr role="separator"> (.menu__sep, 2px).
  6. Destructive row: data-tone="bad", always a trash (or similar) icon and a word.

Accessibility

Menu screen reader and other behaviour
InteractionBehaviour
Screen readerThe button is "Deck options, menu button, collapsed / expanded". On open, focus lands on a row: "Rename, menu item, 1 of 5". Checkable rows add "checked / not checked"; unavailable rows add "dimmed".
Roving focusRows are reached with the arrows, not Tab (tabindex="-1", set when the menu opens). Without JavaScript the popover still opens and closes natively and the rows are ordinary tab stops.
FocusThe focused row inverts and wears a ring inside it in its own text colour (an ink ring on an ink row would vanish). The menu clips at its frame, so nothing is drawn outside it.
TouchRows are 44px (56px in an action sheet), contiguous like any list, so there are no gaps to mis-hit. The action sheet has a Cancel row because a touch screen has no Esc.
Zoom / text sizeThe words grow with the text; a row's padding, its 20px icon and its 44px height do not. The menu scrolls if taller than the screen and is never wider than it. Labels wrap at their spaces. A row's meta text (a reason such as "After review", a shortcut) stays at the end of the row while it fits and otherwise drops under the label, starting where the label starts.
Reduced motionNo 8px settle, no chevron turn, no sheet slide: a fade only.
Forced coloursThe menu and every row keep a border; hover, focus and checked get a 4px Highlight line; unavailable rows are GrayText and dashed.
  • Destructive is never colour alone: it is the trash icon and the word Delete; the red is extra.
  • Unavailable rows use aria-disabled="true", not disabled, so screen reader users can still arrive on them and hear that they exist. Say why in the row's meta text.
  • A tooltip on the menu button is fine but never its only name.
