Select

Pick one from a short list. The closed box is ours, with a chevron slot that fills when you can press it; the list that opens is the browser's, which is the best touch, keyboard and screen reader experience there is.

When to use

Do

Use a select for roughly 5 to 15 options that are known in advance: country, time zone, category. Keep each option short (a word or two: "Monthly", not "Every month"), because the closed box shows one line. Keep the native picker on phones.

Don't

Use it for two to four options (show radio buttons, so everything is visible), for long searchable lists (use a combobox), or for yes / no (use a switch or a checkbox).

Examples

Basic, with a placeholder option

A required select starts on a disabled "Pick one" option so nothing is picked by accident. It reads like placeholder text (--ink-mute, still 4.5:1) until a real value is chosen. Hover or tab in: the end slot fills with the accent and the box lifts, like a button.

Sizes

Grouped options

<optgroup label> gives screen readers and the picker a heading for each cluster, so the options themselves can stay short: the city, not the city and its zone.

Listbox

multiple or size above 1 turns it into a visible list: no chevron, no lift, options at least 44 px tall. Avoid it on phones; a group of checkboxes is easier to use.

States

Rest, hover, focus and pressed come from the same two numbers as a button. Invalid gets a bad-ink frame with an inner second frame, round the whole control, end slot included; disabled is dashed and faint, with no lift and no fill.

Anatomy

  1. Wrapper (.select): the frame. data-size goes here. Raised on hover and focus (--lift).
  2. Native select: borderless inside the wrapper, same frame as a text input (one shared skin). The platform opens its own picker.
  3. End slot: a 44 px block joined to the frame with its own 2px edge. It fills with --accent when the select can be pressed (--fill). It, the chevron and the side padding stay their size at any text size, so the value keeps the room.
  4. Chevron: a mask icon, not a text glyph, over the slot. It ignores taps, so the whole box is one target.
  5. Option list: native. Options and groups get solid role colours so no platform paints its own grey.

Accessibility

Select keyboard and screen reader behaviour
InteractionBehaviour
TabFocuses the select; one tab stop. The wrapper wears the ring.
↑ / ↓Change the value (closed) or move through the list (open). Alt+↓, Space or Enter opens the list; Esc closes it.
TypingType-ahead jumps to the matching option. Native.
Screen reader"Country, combo box, collapsed, Pick one". Required and invalid are announced. The chevron is aria-hidden.
TouchThe whole box is one 44 px-plus target and opens the OS picker (wheel on iOS, sheet on Android).
Zoom / text sizeThe value grows with the text; the end slot, the chevron and the side padding stay their size, so the value keeps the room. A closed select is ONE line: on a 320 px phone at 200% text it holds about 11 characters (about 9 inside a card), so a longer value ends in an ellipsis. The full list is one tap away and nothing is lost, but write options that fit: "Monthly", not "Every month"; put the shared part in the label or an optgroup. In a listbox a name wider than the box ends in an ellipsis too.
Reduced motionNo lift travel; the slot still fills.
Forced coloursThe frame is the control; hover and focus get a 4px Highlight outline; the chevron takes ButtonText.
  • Why not a custom listbox? It would need the full APG combobox or listbox pattern, type-ahead and a mobile sheet, and it would still be worse than the native picker on a phone.
  • Customizable selects (appearance: base-select) are not in Firefox yet. Revisit when they are Baseline.

Tokens used

Everything from Input, plus --accent, --on-accent (slot and chevron), --paper (options), --chrome-hit, --chrome-ic-sm, --chrome-2, --hit (listbox rows), --lift, --fill, --move.
