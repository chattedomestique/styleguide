Decisions

Some choices were the owner's to make and the sheet did not make them. Others were made by default so the work could go on. Each one is written down here with what the guide does now, why, and exactly where to change it.

How to read this page

  • Open means the owner has not answered. The guide ships a default that works, and the answer changes one or two files.
  • Taken means it was decided without the owner and can be undone. The reasons are here so nobody has to rediscover them.
  • To change a decision: edit the files under To reverse, run npm run build and the gate, move the entry to the other list in the same pull request, and add a line to the Changelog. Do not change a default quietly.

Open: waiting for the owner

Open · square by default

Corners: square or soft

Now
Both are built. With no attribute every container is square. data-corners="soft" on <html>, or on any element, rounds the three roles: --radius-card to 24px, --radius-tile to 12px and --radius-ctl to 6px. Circles and pills never change, and no component has corner code in it. The notch card stays square in both.
Why
The owner's committed CSS is square, so square is the default. Most of the reference screens are soft and two are hard-edged, so the guide ships both and lets each app choose.
To reverse
  1. In src/tokens/30-corners.css move :root from the square block to the soft block, and put the square block second: when both match <html>, the later one wins. Keep [data-corners="square"] so an app can still pick it. (00-foundation.css also declares the three roles, but 30-corners.css comes later in the same layer and overrides it.)
  2. In src/js/10-prefs.js change DEFAULT_VALUE.corners to 'soft'. Without this, choosing Square in the appearance panel removes the attribute and leaves soft switched on.
  3. Rebuild, and look at Card, Dock and Sheet.
  4. Change the words "square (default)" in the Shape page, STYLE.md, CLAUDE.md and README.md.

Open · gate 4 is open

Motion

Now
The owner's sheet kept motion closed so it stayed a wireframe. Here it is open: hover, focus and pressed animate --lift and --fill with one transition, sheets and toasts arrive, a spinner turns. Every translate is multiplied by --move, and reduced motion means gentler, never instant. See Motion.
Why
A control that cannot answer your finger, a sheet that cannot slide and a spinner that cannot spin are not finished elements. The order of the pipeline still holds for anything new: structure and states first, then colour, then motion.
To reverse

The switch is gates.motion, which defaults to true, in checkCss in tests/lib/rules.mjs. Set it to false and the lint fails every transition, animation, @keyframes, scroll-behavior: smooth and view-transition-name it finds, which is the list of what to strip.

tests/lint.selftest.mjs proves the switch works. src/tokens/60-motion.css can stay; it is only numbers.

Open · one exception to "flat"

The scrim is the one translucency

Now
--scrim (black at 60%), --scrim-strong (black at 75%) and --on-media (white) in src/tokens/10-color.css. They are the only colours in src/tokens/ with an alpha channel. They dim the page behind a modal Dialog and Sheet and behind the phone form of Menu, dim the content under a Spinner overlay, and sit under text and controls on a photo in Media.
Why
A modal backdrop and text over a photo cannot be flat: without a plate, contrast depends on what the photo happens to be. Rule 2 allows this one exception and names it. npm run test:contrast checks white on the scrim over a white photo, the worst case, at 4.5:1.
To reverse
Components read the roles, so the two values are the only place to change. Make them opaque, for example var(--ink), and the page behind a dialog is hidden instead of dimmed; the contrast check keeps covering them. Then delete the exception from rule 2 in STYLE.md and CLAUDE.md.

Open · the owner's names stand

Names: short, with no prefix

Now
The owner's names are canonical: .card, .btn, --text-xs, --radius-1. There is no class or property prefix. Cascade layers (sg.*) mean an app's own unlayered CSS wins without !important.
Why
The owner's sheet, its rules and its checker all use the short names, so a prefix would rename them everywhere, and in every app built on the sheet. The cost is real: the audit found that unprefixed names can collide with another system's, and Tailwind v4 also defines --text-* properties.
To reverse
There is no switch. A prefix means renaming in src/, docs-src/ and tests/ with a script (the lint reads class and property names from the CSS, so it follows), and renaming in every app that already uses the guide. Do it once, before an app depends on the names. If an app already has its own .card, Upgrade shows how to load the guide beside it.

Open · nothing declared

A licence for the code

Now
Archivo is under the SIL Open Font Licence 1.1 (src/fonts/OFL-Archivo.txt). The Lucide icons are under ISC (src/icons/LICENSE-lucide.txt). The repository's own code has no licence file.
Why
Choosing one is the owner's call and depends on whether the guide is shared.
To reverse
Add a LICENSE file at the root before the repository is shared, and name it in README.md under Credits and licences.

Open · needs a person with a phone

Real devices and assistive technology

Now
Every test runs in Chromium. Not verified anywhere: Safari and iOS (standalone safe areas, Dynamic Type), Firefox, VoiceOver, TalkBack, NVDA, Windows High Contrast on a real machine, and Android font scaling. Contrast numbers come from 8-bit sRGB renderings and ignore display profiles.
Why
Chromium is the only browser that was available where the work was done, and there is no screen reader in a test run.
To reverse
Run the pages on a real iPhone and an Android phone with a screen reader on, following the Manual pass, write down what breaks, and move each finding into the gate as a test where a machine can see it. STYLE.md section 7 lists the known limits and is the place to shorten as they close.

Open · small, none blocks

Small things left

  • A lint for a pressable that forgets to reset --lift and --fill. They inherit, so a button inside a hovered card would draw as pressed; each pressable in the guide resets them by hand and the rule is written in CLAUDE.md.
  • A status table generated from the gates instead of kept by hand. See Status.
  • Numbers written in prose in the docs are not checked against the CSS. Names are (the drift lint); values are not.
  • Magic numbers that are not tokens yet, such as the notch card's 4.5rem.
  • The portrait card's animated flip. The faces are static and the answer simply appears, which is also what reduced motion gets. The owner's app has the recipe (perspective on the parent, backfaces hidden, --ease-flip); how it should move here is a motion decision that has not been made. See Card.
  • No mono, one-bit theme. data-palette="wire" and higher contrast are the nearest, and References says what was and was not taken from the repository that has one.
  • Fonts: Archivo is in three subsets (Latin, Latin extended, Vietnamese). Cyrillic, Greek, Arabic, Hebrew, Indic and CJK fall back glyph by glyph to the next family, which has no width axis. Add a subset in src/tokens/50-fonts.css when an app needs one.

Taken by default

Taken · old name kept

Card: study became portrait

Now
.card--portrait is the tall 5:7 card (--ratio-portrait) and .card__hero is its big subject. The owner's names, .card--study and .card__answer, are aliases and keep working. tests/components/card.mjs has a test that the old name still does.
Why
"Study" is one app's word. A shared foundation should not carry a product's vocabulary, and a ticket or a poster is the same card.
To reverse
To make study the name again, swap the names in the two :is(…) lists and the .card__hero rule in src/components/card.css, in the Card page, and in the spec. To drop the aliases, delete .card--study and .card__answer from those places. An app that still uses the old names breaks the day the alias goes.

Taken · the owner's font

Archivo, not Manrope

Now
Archivo Variable, self-hosted: weight 100 to 900, width 62% to 125%. One family does the work of two: expanded for the display line, normal for reading, condensed for labels. The stack is "Archivo", "Helvetica Neue", Helvetica, Arial, sans-serif.
Why
The first draft of this repository used Manrope. Manrope is on the owner's own banned-default list: the lint refuses a default font as the first family of any --font-* (BAD_FONTS in tests/lib/rules.mjs). The owner's sheet uses Archivo, and its width axis is what makes a second family unnecessary.
To reverse
  • Change --font-sans in src/tokens/00-foundation.css, the @font-face blocks in src/tokens/50-fonts.css and the files in src/fonts/.
  • A family with no width axis ignores the expanded, condensed and semi-expanded keywords in --type-display, --type-label and --type-figure, so the three voices become one. Pick a second family for labels, or accept it.
  • Anything on the banned list also has to come off BAD_FONTS, and that is a decision to write down here.

Taken · brand-agnostic

The default palette is neutral

Now
With no data-palette, colour is neutral greys with an ink accent: black on light, white on dark. The six tone slots carry the Flashcards hues (yellow, blue, coral, green, violet, orange) as pastels. In higher contrast the accent collapses to ink. mint, periwinkle, sand, cream and wire are one attribute away.
Why
The guide serves many apps, so no brand colour is baked in. Colour is a swap (rule 6) and the wireframe stage was already grey.
To reverse
To give every app an accent, set the --k-accent-* knobs in the :root block of src/tokens/10-color.css; to make a palette the default, copy its block from src/tokens/40-palettes.css into :root. Run npm run test:contrast: the lightness gaps are what keep the pairs legible, so keep them.

Taken · above the floor

7:1 text and 44px targets by default

Now
WCAG 2.2 AA is the floor everywhere. The defaults are higher: --ink and --ink-soft at 7:1, frames and the focus ring at 3:1, placeholder text at 4.5:1, every target 44px (--hit) with 8px between targets. AA asks for 24px.
Why
The hit-target token is the owner's. These apps are used one-handed on a phone, in sunlight, by people of every age. The cost of the higher bar is small and the cost of missing it is paid by the reader.
To reverse
Loosening it is not recommended. If you must, the gaps are the --k-* lightness knobs in src/tokens/10-color.css, the minimums are the PAIRS in tests/contrast.mjs, and the size is --hit in src/tokens/00-foundation.css. Change the test and the docs in the same pull request as the knob.

Taken · a fix to the original

Layer order: wireframe below components

Now
The order is sg.reset, sg.tokens, sg.base, sg.layout, sg.wire, sg.components, sg.utilities. .sr-only and .num live in sg.utilities, so they beat a component's position and font.
Why
In the owner's original the wireframe layer sat above the components and erased a disabled notch card's silhouette: a placeholder must never override a real element. The audit called it out (finding M8).
To reverse
Change LAYER_ORDER in scripts/build.mjs. Each source file opens its own @layer sg.x block, and the build fails on an unknown layer name.

Taken · so apps can copy a file

Generated files are committed

Now
dist/ and docs/ are built by npm run build and committed. Nobody edits them by hand. npm run build:check fails when they are stale, and CI runs it.
Why
An app copies files out of dist/ with no build step, and GitHub Pages serves docs/ as it is.
To reverse
Add dist/ and docs/ to .gitignore, remove them from git, drop the build:check step from .github/workflows/ci.yml, and build on release instead. Apps then have to build the guide themselves or take it from a release.

Taken · so the gate is not voluntary

CI runs the gate

Now
.github/workflows/ci.yml runs on every push to main and every pull request. A first job runs the lint, the lint self-test and npm run build:check. A second builds, then runs the contrast matrix, the component specs and the accessibility gate in Chromium. A pull request runs two appearances of the accessibility gate per page; a push to main runs all five.
Why
The audit found that enforcement was voluntary: a check nobody runs protects nothing. The fast checks run first, so a stale dist/ or a colour literal is reported before the slow browser tests start.
To reverse
Delete the workflow, or change --quick in its accessibility step to run all five appearances on pull requests too (slower). Nothing else depends on it. Testing describes each command.

Taken · one look

No second surface style

Now
There is one look. data-corners is the only switch that changes shape, and it changes three radius roles and nothing else. There is no data-surface.
Why
The first draft had three surface styles and soft, blurred shadows. A reference screen even proposed a hard surface as a token set beside a soft one. The owner's sheet has one look, rules 1 and 2 forbid a soft shadow, and every extra style doubles what must be tested. The first draft was replaced rather than patched.
To reverse
Add an attribute with its own block of role overrides, in the manner of src/tokens/30-corners.css, and a row for it in the appearance panel in docs-src/assets/docs.js. The lint would still refuse blur and blurred shadows in it: to allow those you would be changing rule 2, which is the owner's.
