Status

Every element moves through six gates, in order. This page records what has been checked for each one, by machine and by eye, and nothing more. Card and Button are the owner's two and are waiting for sign-off; the rest were built since, and none has been signed off.

The gates

The full list, with the question each gate asks, is on Contributing: 0 brief, 1 wireframe, 2 states, 3 colour, 4 motion, 5 freeze. Gate 5 is the owner's: an element is frozen when its docs are complete, its accessibility gate is green, its screenshots have been looked at, and the owner has said so.

Everything built since

Last run of the checks: 2026-10-01, on the merged tree of every slice. Each row has two fields, and each says only what was checked.

  • Automated checks reads pass when three things hold at once: the element's spec in tests/components/ passes, npm run lint reports no error, and its page passes npm run test:a11y in all five appearances. Otherwise it reads fail, with the findings in Open items, or not run. A pass proves what those checks measure: keys, states, names, contrast, targets, no text cut off and no sideways scrolling at 320px and at 200% text. It does not prove that the element looks right.
  • Screenshots says whether a person has looked at the element's demos at 390px with 100% and with 200% text, and at 1024px, since its last change: in review, changes needed or reviewed, with the date. Equal heights in a row, no lonely item, no word broken inside, icons beside their labels: only a person checks those.

Gates 1 to 4 include looks (the squint test in data-palette="wire", the states as drawn), so an element is ready for the owner only when its checks pass and its screenshots are reviewed. Gate 5 is awaiting sign-off for every element: nobody has signed one off.

How this table is kept

  • It is generated, so that nobody types a status. npm run status runs the build, the lint, the component specs and the accessibility gate, and rewrites this page from their output (about an hour for all five appearances; npm run status -- --quick runs two and is for looking, not for committing). Run npm run build afterwards so docs/ matches; CI fails otherwise.
  • STYLE.md section 6 keeps the owner's own two rows, Card and Button: when either moves, copy its row there in the same pull request, and add a line to the Changelog.
  • To refresh only the evidence, run the three commands yourself: npm run lint, npm run test:components and npm run test:a11y. Automated checks only ever reads pass because the checks passed. Gate 5 is the owner's sign-off and is never filled in by the script.
  • Screenshots is kept by hand in docs-src/project/visual-review.json, one entry per element: { "button": { "state": "reviewed", "date": "2026-10-02" } }. The states are in review (being looked at, or changed since the last look), changes needed and reviewed. Whoever reviews the screenshots changes the entry after looking (390px at 100% and 200% text, and 1024px), sets it back to in review when the element changes, and regenerates this page: from the last run's logs, which npm run status keeps in test-results/ (the header of scripts/status.mjs shows how), so nothing has to run again. No script writes the file.
  • Everything here was measured in Chromium. Nothing has been verified in Safari, Firefox or with a screen reader; see Decisions.
