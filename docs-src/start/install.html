Install

The guide is plain files. Copy them into your app or link a tagged release. There is no package to install and no build step for your app.

What is in dist/

npm run build in the guide's repository writes everything an app needs to dist/. Nothing else in the repository is for apps.

Icon licence

The icons that are not the owner's come from Lucide (ISC licence), re-stroked to the guide's line. The ISC licence asks that its copyright and permission notice stay with copies. dist/icons.css names Lucide in its banner comment but does not carry the licence text, which lives in src/icons/LICENSE-lucide.txt in the repository. If you ship icons.css, add that file to your app's third-party notices. The font's licence, OFL-Archivo.txt, is already in dist/fonts/.

Option A: copy the files (recommended)

Best for anything installed or offline. The files are same-origin, they go into your precache, and no third party is involved.

  1. In the guide's repository run npm run build, or take dist/ from a tagged release.
  2. Copy what you need into your app and keep the structure:
my-app/
  index.html
  styleguide/
    styleguide.min.css
    styleguide.js
    icons.css                               (optional, see Icons)
    fonts/
      archivo-latin-var.woff2
      archivo-latin-ext-var.woff2
      archivo-vietnamese-var.woff2
      OFL-Archivo.txt
  1. Reference the files with relative URLs, as in the complete index.html below.

The fonts must sit in fonts/ next to the CSS

The stylesheet asks for url("fonts/archivo-latin-var.woff2"). A URL inside a stylesheet is relative to the stylesheet, not to your page. Move the CSS into another folder, or bundle it somewhere else, and that request returns 404. The page still works (text falls back to Helvetica or Arial, with no width axis, so condensed labels look wider), but it is no longer Archivo.

Two fixes: keep fonts/ beside the CSS, or declare the face again in your own CSS with the path you want. Declared after the guide's, the later rule wins and the original file is never requested (checked in Chromium: only the new URL was fetched).

/* In your own CSS, loaded after styleguide.css. */
@font-face {
  font-family: "Archivo";
  src: url("/assets/archivo.woff2") format("woff2");
  font-weight: 100 900;
  font-stretch: 62% 125%;
  font-style: normal;
  font-display: swap;
}

This one face has no unicode-range, so it covers every character. Copy the latin-ext and vietnamese files only if you need them and then keep their ranges.

Option B: link a tagged release from jsDelivr

Good for a prototype: nothing to copy. jsDelivr serves any tag of a public GitHub repository, and pins a tag as immutable.

<link rel="preload" href="https://cdn.jsdelivr.net/gh/chattedomestique/styleguide@v0.2.0/dist/fonts/archivo-latin-var.woff2" as="font" type="font/woff2" crossorigin>
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/chattedomestique/styleguide@v0.2.0/dist/styleguide.min.css">
<script src="https://cdn.jsdelivr.net/gh/chattedomestique/styleguide@v0.2.0/dist/styleguide.js" defer></script>
Do not use raw.githubusercontent.com, and do not use @main

Headers checked on 30 September 2026: raw.githubusercontent.com answers with content-type: text/plain and x-content-type-options: nosniff, so a browser refuses the file as a stylesheet or a script. A jsDelivr tag URL answered text/css with access-control-allow-origin: * and cache-control: public, max-age=31536000, immutable. A branch URL such as @main is not immutable: it is cached for a while and changes under you.

  • The tag in the example does not exist yet. On 30 September 2026 the repository had no tags (GitHub's tags API returned an empty list), so the URL above returns 404 until you push v0.2.0 (see Upgrade). The URL shape is jsDelivr's documented one, checked against another project's tag; this repository has never served the guide through jsDelivr.
  • It is a runtime dependency. Offline, the first load fails unless your service worker has cached the three URLs, and a cross-origin stylesheet can only be cached in cors mode. For an installed app use Option A.
  • The preload must use the same full URL as the one the CSS resolves to, with crossorigin.
  • Optional integrity check. A tag never changes, so you can pin its hash with integrity="sha384-…" and crossorigin="anonymous" on the stylesheet link. A wrong hash blocks the file.
openssl dgst -sha384 -binary dist/styleguide.min.css | openssl base64 -A

Only some elements

Newer builds of the guide also write the main file in pieces, so an app can link only what it uses. dist/core.min.css holds the tokens, base, layout and utilities (everything but the elements); dist/elements/<name>.min.css is one element; dist/core.min.js is SG, the prefs, the guard and the disclosure helper; dist/js/<NN-name>.min.js is one element's script. dist/elements/manifest.json says which elements each one builds on and which script each needs. If your dist/ has no core.css, use the one file above.

<link rel="stylesheet" href="styleguide/core.min.css">
<link rel="stylesheet" href="styleguide/elements/button.min.css">
<link rel="stylesheet" href="styleguide/elements/card.min.css">
<link rel="stylesheet" href="styleguide/elements/toast.min.css">
<script src="styleguide/core.min.js" defer></script>
<script src="styleguide/js/63-toast.min.js" defer></script>
  • Order matters: core first, then the elements, then core.min.js, then the scripts of the elements you linked. Each element file repeats the layer order, so it cannot arrive in the wrong layer.
  • Checked with exactly the six lines above: the button drew its 2px pill frame, SG.prefs and SG.toast were defined and a toast showed. The toast's status icons live in icons.css.
  • If an element lists others under buildsOn in the manifest, link those too: it reads their private properties.
  • Palettes, tones and corners are part of core and cannot be left out.

The head

Each line is in the complete file further down. None is decoration: each prevents a specific failure.

Head elements and why each is needed
ElementWhy
<html lang="en">Screen readers choose a voice and pronunciation from it (WCAG 3.1.1). Set it to the language of the page.
viewport with viewport-fit=coverWithout cover every env(safe-area-inset-*) is 0 and content can sit under a notch or the home indicator; the app shell and the --safe-* tokens rely on it. interactive-widget=resizes-content makes Chrome on Android shrink the layout when the keyboard opens; iOS Safari ignores it. Never add maximum-scale or user-scalable=no: they block pinch zoom (WCAG 1.4.4), and the guide's lint and axe both flag them.
color-scheme = light darkNative controls, scrollbars and the page background before the CSS arrives follow the OS scheme. The CSS sets the same value on :root.
Two theme-color metas with mediaColour the browser toolbar to match the canvas in light and dark. Use the pair in the table below. When a person overrides the theme or palette in your settings, SG.prefs rewrites both tags to the live canvas colour.
Inline prefs scriptApplies the saved theme, contrast, palette, corners and motion to <html> before the first paint, so a dark-mode user does not see a white flash. It must be inline and in the head, and it is wrapped in try/catch for private windows.
<link rel="preload"> for the latin fontStarts the download before the CSS is parsed. crossorigin is required even on the same origin, because fonts are always fetched in CORS mode; without it the file is fetched twice. The complete file below made one request for the font. Drop the preload if you change the font.
Stylesheet, then styleguide.js with deferA deferred script runs after the page is parsed and before DOMContentLoaded, so SG exists for your own code in a DOMContentLoaded handler or a later deferred script.
text-scale = scale (optional)<meta name="text-scale" content="scale"> asks Chrome and Edge on Android (version 146 and later, per the compatibility data) to scale rem text with the OS font size. Other browsers ignore it. Not verified on a device. It scales only text set in rem or em, and can cause sideways scrolling in layouts that use px. The guide uses rem throughout, but it is not in the complete file below because nobody has seen it work.

theme-color values for each palette

A complete minimal index.html

Save this next to a styleguide/ folder laid out as above and serve it over http. Any static server works: npx serve in the app folder, or node scripts/serve.mjs /path/to/my-app from the guide's repository (it listens on 127.0.0.1 only). It uses the app shell, the type styles, the layout primitives, the button and two icons, nothing else.

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover, interactive-widget=resizes-content">
  <meta name="color-scheme" content="light dark">
  <meta name="theme-color" content="#f5f5f5" media="(prefers-color-scheme: light)">
  <meta name="theme-color" content="#0e0e0e" media="(prefers-color-scheme: dark)">
  <title>Today · Tasks</title>
  <link rel="icon" href="data:,">

  <!-- Apply the saved appearance before first paint (no flash of the wrong theme). -->
  <script>try{var p=JSON.parse(localStorage.getItem('sg:prefs')||'{}');for(var k in p)document.documentElement.setAttribute('data-'+k,p[k])}catch(e){}</script>

  <link rel="preload" href="styleguide/fonts/archivo-latin-var.woff2" as="font" type="font/woff2" crossorigin>
  <link rel="stylesheet" href="styleguide/styleguide.min.css">
  <link rel="stylesheet" href="styleguide/icons.css">
  <script src="styleguide/styleguide.js" defer></script>
</head>
<body>
  <a class="skip-link" href="#main">Skip to content</a>

  <div class="app safe-top">
    <main class="app__main stack" id="main" tabindex="-1">
      <p class="t-label">Tasks</p>
      <h1 class="t-title">Today</h1>
      <p class="t-meta"><span id="count" class="num">3</span> tasks left</p>
      <div class="cluster">
        <button class="btn" data-variant="primary" type="button" id="add"><span class="ic ic--plus" aria-hidden="true"></span>Add task</button>
        <button class="btn" type="button" id="reset"><span class="ic ic--rotate-ccw" aria-hidden="true"></span>Start over</button>
      </div>
    </main>
  </div>

  <script>
    // styleguide.js is deferred: it runs before DOMContentLoaded, so SG exists here.
    document.addEventListener('DOMContentLoaded', function () {
      var count = document.getElementById('count');
      var n = 3;
      function show(message) { count.textContent = n; SG.announce(message); }
      document.getElementById('add').addEventListener('click', function () { n += 1; show('Task added. ' + n + ' tasks left'); });
      document.getElementById('reset').addEventListener('click', function () { n = 3; show('Back to 3 tasks'); });
    });
  </script>
</body>
</html>

What was checked, by loading this exact file in Chromium at 390 px wide: no console errors and no failed requests; the latin font loads, and with the preload it is requested once; Tab lands on the skip link first and Enter moves focus to <main>; Add task changes the count and puts "Task added. 4 tasks left" into a polite live region; axe reports no violations; a saved dark theme is applied again after a reload. Not checked: Safari, Firefox, any phone.

file:// works, with one console error

Opened straight from disk the page, its styles and the font all work. The preload with crossorigin logs a CORS error on file:// because browsers treat each file as its own origin; the font still loads through the stylesheet, and without the preload there is no error at all. Use http for real testing: service workers need it anyway.

Let people choose: SG.prefs

Give every app a settings screen with these five controls; some people cannot change the operating system's. SG.prefs stores the choices under the sg:prefs key in localStorage and applies them as attributes on <html>; the inline snippet in the head applies them again before first paint.

SG.prefs.set('palette', 'mint')       // theme | contrast | palette | corners | motion
SG.prefs.set('theme', 'system')       // "system" removes the attribute: follow the device
SG.prefs.get('theme')                 // "system" | "light" | "dark"
SG.prefs.all()                        // { theme: "system", contrast: "system", palette: "default", corners: "square", motion: "system" }
SG.prefs.onChange(function (name, value) { /* keep your settings screen in step */ })
SG.prefs.reset()                      // forget everything, follow the device
Known limit: the guide's defaults cannot be saved as a choice over your own default

"No attribute" is the default, so default and square are stored as nothing. If your HTML says data-palette="mint" and a person picks default, the attribute is removed and nothing is stored, so the next page load is mint again. SG.prefs.reset() also removes the attributes you wrote until the next load. Checked in Chromium. Until SG.prefs can store an explicit default, either leave the look in the HTML alone and do not offer default and square as choices when your app's own look differs, or treat "never saved" as your app's default in the head snippet (localStorage.getItem('sg:prefs') === null): that way a saved {} means "they chose the guide's default". The second way was tried and works, with one wart: choosing the default palette also drops your default corners on the next load.

Icons

Icons are CSS masks, so they take the text colour and need no sprite:

<button class="btn" type="button">
  <span class="ic ic--plus" aria-hidden="true"></span>Add task
</button>
  • Five are built in (arrow, plus, minus, close, check). Every other name needs icons.css linked after the main file. Browse them on the Icons page.
  • An icon with no mask paints a solid square. Use a name that does not exist, or forget icons.css, and the span is a 20 px block of text colour (checked). The build fails for a missing name in this site's own pages; your app needs a look at the screen.
  • Icons are decorative by default. They are aria-hidden; when one is a control's only content, the control carries the aria-label. Size them with --ic-size (default 1.25rem).

Content Security Policy

Two things in the guide meet a strict policy: the one inline script, and the icon masks.

  1. The prefs snippet is inline. Allow that one script by hash. The hash is over the exact text between the tags, so whitespace matters; this prints it for the snippet as written in the complete file above: 
    printf '%s' "try{var p=JSON.parse(localStorage.getItem('sg:prefs')||'{}');for(var k in p)document.documentElement.setAttribute('data-'+k,p[k])}catch(e){}" | openssl dgst -sha256 -binary | openssl base64 -A
    Put the result in script-src 'self' 'sha256-…'. Without it the snippet is refused (checked), and the saved look is applied a moment later by styleguide.js: you keep the theme but lose the no-flash guarantee.
  2. The icon masks are data: URIs. A policy of default-src 'self' alone refuses them as images and every icon paints as a solid square (checked: "Refused to load the image 'data:image/svg+xml…'"). Add img-src 'self' data:.
Content-Security-Policy: default-src 'self'; script-src 'self' 'sha256-HASH-FROM-ABOVE'; img-src 'self' data:

Checked in Chromium with exactly this policy. The guide's own CSS has no inline styles, so it needs nothing in style-src. Inline style="…" attributes in your own markup (the docs here use style="--grid-min: 14rem") are blocked by a strict style-src; put them in a class instead.

Caching and offline

  • File names are not hashed. styleguide.min.css is the same URL in every release, so a browser or service worker can keep serving an old copy. Put the version in the folder name (styleguide-0.2.0/) or bump your service worker's cache name on every upgrade.
  • Precache your HTML, the CSS, styleguide.js, the latin font, icons.css if you use it, and the latin-ext and vietnamese fonts if your content needs them. The PWA page has a working service worker.
  • Static hosts cache briefly. GitHub Pages answered with max-age=600 when measured during the research for this guide, so allow ten minutes of stale files after a deploy, or use the versioned-folder approach.
  • Which version does an app have? Both CSS files start with a banner: head -c 120 styleguide/styleguide.min.css prints /*! styleguide v0.2.0 …. There are no source maps.

Check that it works

Paste into the browser console on your page:

document.fonts.check('16px "Archivo"')                                   // true once the font is ready
typeof SG                                                              // "object"
getComputedStyle(document.documentElement).getPropertyValue('--hit')   // "2.75rem"
SG.prefs.all()   // { theme: "system", contrast: "system", palette: "default", corners: "square", motion: "system" }

All four gave those answers on the complete file above. document.fonts.check is also true when nothing on the page needs the font, so it proves the font is usable, not that it was fetched: look at the Network tab for archivo-latin-var.woff2.
