PWA

An installed app has no browser around it: nothing to go back, nothing to refresh, no address to tell you where you are. This page makes an app on the guide installable, lets it start offline, and says what it looks like when the connection goes.

What was and was not seen

Everything on this page was run in Chromium 141 on Linux: the manifest was parsed, installability was asked of the browser, a service worker installed, reloaded offline and updated. Nothing was run on an iPhone or an Android phone. Install on a real device, the maskable icon on a real launcher, standalone safe areas, the iOS status bar and Dynamic Type are all listed under What could not be verified. The example app is called Tasks; it is the complete minimal file from Install with the additions below.

Link it: the head additions

Add these to the head of the complete file:

<link rel="manifest" href="manifest.webmanifest">
<link rel="icon" href="icons/icon-192.png" type="image/png">
<link rel="apple-touch-icon" href="icons/apple-touch-icon-180.png">
<meta name="mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-title" content="Tasks">
<meta name="apple-mobile-web-app-status-bar-style" content="default">
  • apple-touch-icon is an opaque 180 px PNG. Safari uses it for the Home Screen icon and does not use an SVG favicon for that; according to the compatibility data it falls back to the manifest's any icons only when there is no touch icon. (Not seen on a device.)
  • Both capable tags: Safari reads the apple-mobile-web-app-* family, and mobile-web-app-capable is the standard name for the same idea. Keep both.
  • Changes to the status-bar style are not picked up by an app that was already added (WebKit bug 260508, open since 2023). Treat the Apple metadata as read when the app is added; to see a change, remove the app and add it again.

  'icon-512.png': { size: 512, fill: 1, background: null },

Standalone display and safe areas

With display: standalone the browser's back button, reload button and address bar are gone. Build them in:

  • A way back on every screen but the first: the App bar's named back control, or a Breadcrumb. Nothing important may be reachable only by an edge swipe, which collides with the system's back gesture.
  • A way to refresh: a visible control, or pull-to-refresh with a button beside it (every gesture has a tap equivalent).
  • Know you are installed when it matters: matchMedia('(display-mode: standalone)').matches, or navigator.standalone === true on iOS. Use it to hide "Install" and, in CSS, @media (display-mode: standalone) to hide an "Open in browser" link.
  • Do not lock orientation, and keep the dock and the app bar in --dock-h and --appbar-h so focus is never hidden behind them (WCAG 2.4.11).

The shell does what it can without a device. viewport-fit=cover makes env(safe-area-inset-*) real; .app pads the left and right by max(var(--gutter), var(--safe-left)) and its right twin (landscape phones have side insets), .safe-top and .safe-bottom are there for bars and docks, and everything full-height uses 100dvh, never vh. Nothing in the shell depends on the top inset being non-zero, for the reason in the next box.

iOS may report a safe area of 0 and still draw a system strip

WebKit bug 301994 ("Status bar remains visible in fullscreen mode in Home Screen web apps") began on iOS 26.1, when a reporter found that env(safe-area-inset-top) now returned 0. Reporters said 26.2 fixed it; on 21 July 2026 one measured it again on iOS 26.5.2: screen.height 874 against innerHeight and 100dvh of 812, a 62 px gap "drawn by the system above the web layer and unreachable by any DOM element", and a strip colour taken from the page background that updates only when the app is relaunched. An Apple engineer confirmed it on iOS 27 beta and reopened the bug on 5 August 2026. Status when checked on 30 September 2026: reopened, last changed 28 August.

What to do: set the page background (html { background: var(--canvas) } is already in the guide), so the strip matches; do not assume the viewport is as tall as the screen; use a flex column, not position: fixed full-height layers; do not use apple-mobile-web-app-status-bar-style: black-translucent on a light page (community reports say it forces white glyphs, which is not documented by Apple). None of this was tested on a device.

Service worker

A worker is what lets the app start with no network. It is not needed to install. This one precaches the shell (the files the app cannot run without), answers every page navigation with that shell, and keeps everything else fresh in the background. It is the tested code.

/* sw.js: offline app shell. Bump VERSION on every deploy that changes a precached file. */
const VERSION = 'v1'
const SHELL = `shell-${VERSION}`          // precached, cache-first, replaced as a whole on update
const RUNTIME = 'runtime'                 // everything else: stale-while-revalidate
const RUNTIME_MAX = 60
const PRECACHE = [
  './',
  './index.html',
  './app.js',
  './manifest.webmanifest',
  './styleguide/styleguide.min.css',
  './styleguide/icons.css',
  './styleguide/styleguide.min.js',
  './styleguide/fonts/archivo-latin-var.woff2',
  './icons/icon-192.png',
]

self.addEventListener('install', (event) => {
  event.waitUntil((async () => {
    const cache = await caches.open(SHELL)
    // cache: 'reload' skips the HTTP cache, so a host that sends max-age cannot hand the worker stale files
    await cache.addAll(PRECACHE.map((url) => new Request(url, { cache: 'reload' })))
    // No skipWaiting() here: the page offers the update and asks for it.
  })())
})

self.addEventListener('activate', (event) => {
  event.waitUntil((async () => {
    for (const key of await caches.keys()) if (key.startsWith('shell-') && key !== SHELL) await caches.delete(key)
    await self.clients.claim()
  })())
})

self.addEventListener('message', (event) => {
  if (event.data && event.data.type === 'SKIP_WAITING') self.skipWaiting()
})

self.addEventListener('fetch', (event) => {
  const req = event.request
  if (req.method !== 'GET') return                        // never touch writes
  const url = new URL(req.url)
  if (url.origin !== self.location.origin) return         // never touch other origins or APIs

  if (req.mode === 'navigate') {                          // any page address gets the shell
    event.respondWith((async () => {
      const shell = await caches.open(SHELL)
      return (await shell.match(req, { ignoreSearch: true }))
        || (await shell.match('./index.html'))
        || fetch(req)
    })())
    return
  }

  event.respondWith((async () => {
    const hit = await (await caches.open(SHELL)).match(req)
    if (hit) return hit
    const runtime = await caches.open(RUNTIME)
    const cached = await runtime.match(req)
    const network = fetch(req).then(async (res) => {
      if (res.ok && res.type === 'basic') {
        await runtime.put(req, res.clone())
        const keys = await runtime.keys()
        for (const k of keys.slice(0, Math.max(0, keys.length - RUNTIME_MAX))) await runtime.delete(k)
      }
      return res
    })
    if (cached) { event.waitUntil(network.catch(() => {})); return cached }
    return network
  })())
})

Register it, and offer updates

The page registers the worker, offers a waiting update and shows the connection. The update is a Toast with an action, because an update is something the person decides about, and a toast with an action stays until dismissed.

The script needs two additions to the complete file: a line that loads it after the guide's script, and the banner it shows and hides. The banner is the same banner row the demo below uses. Put it first inside <main>, so it sits above the content on every screen.

<!-- in the head, after the guide's script -->
<script src="app.js" defer></script>

<!-- first child of <main> -->
<div class="card alert" data-tone="warn" data-size="sm" id="offline" hidden>
  <div class="card__body">
    <span class="ic ic--wifi-off" aria-hidden="true"></span>
    <div class="alert__main"><p class="alert__text"><span class="sr-only">Warning: </span>You are offline. Changes sync when you reconnect.</p></div>
  </div>
</div>
/* app.js: register the worker, offer updates, show the connection state. */
(function () {
  'use strict'

  /* --- service worker + update prompt ------------------------------------------ */
  if ('serviceWorker' in navigator) {
    navigator.serviceWorker.register('./sw.js', { scope: './', updateViaCache: 'none' }).then(function (reg) {
      function offer(worker) {
        SG.toast.show({
          message: 'A new version is ready.',
          persistent: true,
          action: { label: 'Reload', onClick: function () { worker.postMessage({ type: 'SKIP_WAITING' }) } },
        })
      }
      if (reg.waiting && navigator.serviceWorker.controller) offer(reg.waiting)
      reg.addEventListener('updatefound', function () {
        var w = reg.installing
        w.addEventListener('statechange', function () {
          if (w.state === 'installed' && navigator.serviceWorker.controller) offer(w)
        })
      })
      // An installed app is rarely cold-started: look for updates whenever it comes back to the front.
      document.addEventListener('visibilitychange', function () {
        if (document.visibilityState === 'visible') reg.update().catch(function () {})
      })
    })
    var reloading = false
    navigator.serviceWorker.addEventListener('controllerchange', function () {
      if (reloading) return
      reloading = true
      location.reload()
    })
  }

  /* --- connection state: a hint, never a gate ---------------------------------- */
  var banner = document.getElementById('offline')
  function sync() {
    var off = !navigator.onLine
    if (banner.hidden === !off) return
    banner.hidden = !off
    SG.announce(off ? 'You are offline. Changes sync when you reconnect.' : 'Back online.')
  }
  window.addEventListener('online', sync)
  window.addEventListener('offline', sync)
  sync()
})()

What was checked

Served from http://127.0.0.1 with the guide's dist files and the code above, in Chromium:

  • First load installs the worker; the next load is controlled by it, and the shell cache held the nine precached files.
  • With the network switched off, a reload rendered the page, with its font; so did /?utm=1.
  • After editing index.html and bumping VERSION, registration.update() found a waiting worker while the page still showed the old version, and the toast appeared. Pressing Reload made exactly one reload, the page showed the new version, and caches.keys() was ["runtime", "shell-v2"]: the old shell cache was gone.

Rules that keep it from biting

  • Bump VERSION on every deploy that changes a precached file. A byte change in sw.js is what triggers an install, and the cache name is how old files are dropped. Forget it and installed copies keep the old CSS.
  • Never call skipWaiting() by itself. Swapping the worker under a page that is open pairs new scripts with old markup and loses a half-filled form. Offer the update and let the person press it.
  • updateViaCache: 'none' and cache: 'reload' stop the HTTP cache from handing the worker a stale copy of itself or of the files it precaches. GitHub Pages answered with max-age=600 when measured during the research.
  • An installed app is rarely cold-started, so it checks for an update when it becomes visible again, not only at launch.
  • Navigations are cache-first from a versioned cache, not stale-while-revalidate: refreshing index.html in the background into the old cache would pair new markup with old assets.
  • Real paths need absolute URLs. The worker answers /some/deep/route with index.html, and relative URLs in that file then resolve against the deep path: in the test, six requests went to paths under /some/deep/ and returned 404. Use root-relative or <base href> URLs, or hash routes, if your app has paths.
  • Storage belongs to the origin, not the path. localStorage, IndexedDB and Cache Storage are shared by every app on user.github.io. Prefix cache names and storage keys with the app's id. The guide's own key, sg:prefs, is shared by every app on the origin unless you set <html data-sg-prefs-key="myapp:prefs"> (and use the same string in the head snippet).
  • Precache the other font files (archivo-latin-ext-var.woff2, archivo-vietnamese-var.woff2) if your content can contain those characters; otherwise offline they fall back to another font.
  • The worker never touches writes or other origins. Queue writes yourself (IndexedDB) and retry on online and when the app becomes visible; Background Sync is Chromium-only.

The offline state

Offline is a state the person should see and understand, not an error. Three elements from the guide cover it, and each has a different job:

Which element shows which part of being offline
ElementShowsWhen
Alert, banner row"You are offline. Changes sync when you reconnect."While offline, above the content, on every screen. It is state, so it stays until the state ends.
Empty state, the offline kind"You're offline. Saved decks still work." with a way to open what is savedOnly where a screen has nothing to show without a connection. It replaces the missing content; it does not sit on top of content you have.

Install prompts

Chromium can tell the page that it is installable (beforeinstallprompt, Chromium only). Safari cannot, so on iPhone you explain where the command is. Either way: no pop-up on the first visit, a button in Settings where a person looks for it, and nothing at all once the app is installed.

/* install.js: offer "Install" only where the browser can install, and only when the person asks. */
(function () {
  'use strict'

  var standalone = matchMedia('(display-mode: standalone)').matches || navigator.standalone === true
  if (standalone) return                              // already running as an app: show nothing

  var button = document.getElementById('install')     // <button class="btn" hidden>Install Tasks</button>
  var help = document.getElementById('install-help')  // a hidden card that explains Share, then Add to Home Screen
  var saved = null

  // Chromium fires this when the app is installable. Keep the event; do not interrupt the first visit.
  window.addEventListener('beforeinstallprompt', function (event) {
    event.preventDefault()
    saved = event
    button.hidden = false
  })

  button.addEventListener('click', function () {
    if (!saved) return
    saved.prompt()
    saved.userChoice.then(function (choice) {
      SG.announce(choice.outcome === 'accepted' ? 'Installing Tasks.' : 'Not installed. You can install from Settings later.')
      saved = null
      button.hidden = true
    })
  })

  window.addEventListener('appinstalled', function () {
    button.hidden = true
    SG.announce('Tasks is installed.')
  })

  // Safari has no install event. On iPhone and iPad, say where the command is (iPadOS reports itself as a Mac).
  var apple = /iphone|ipad|ipod/i.test(navigator.userAgent) || (navigator.platform === 'MacIntel' && navigator.maxTouchPoints > 1)
  if (apple) help.hidden = false
})()
