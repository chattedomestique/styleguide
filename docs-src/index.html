Style Guide

One small, accessible design system for every app you build: clean, friendly and clear about what to do next. Copy one CSS file, pick a palette, and get consistent screens.

Use it in an app

  1. Copy dist/styleguide.css, dist/fonts/ and (optionally) dist/styleguide.js and dist/icons.svg into your app. No build step.
  2. Link the stylesheet and set the viewport and colour-scheme meta tags. The PWA starter has a correct, minimal <head>.
  3. Write HTML with the component classes. Choose a look with three attributes on <html>: data-palette, data-surface and (optionally) data-theme.
<html lang="en" data-palette="mint" data-surface="soft">
  <link rel="stylesheet" href="styleguide.css">
  <button class="btn">Add funds</button>

Principles

  • Guide the user. One primary action per screen. Big, clear targets. Labels say what happens. Colour supports meaning but never carries it alone.
  • Accessible by construction. Colour pairs are built from fixed lightness gaps, then verified in a browser for every theme, palette and contrast mode. WCAG 2.2 AA is the floor; 7:1 text and 44 px targets are the default.
  • One system, many looks. Palettes change colour, surface styles change shape (soft, pop, hard), themes change light and dark. Components never know which is active.
  • Gentler, not instant. Reduced motion replaces travel with fades; it never turns the app into jump cuts.
  • Growable. Adding a component is a documented, checklisted routine. See Adding to the guide.

Try it

Open Appearance at the top right and change the theme, palette, surface style, contrast or motion. Every page on this site, including this one, updates live.
