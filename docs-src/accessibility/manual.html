Manual testing

The checks that need a person and a device. Every automated test in this repository runs in Chromium on Linux; none has seen a phone, a screen reader or Windows High Contrast. This page is the script for that pass.

Nobody has run these scripts

Every line below is a script, not a result. Nothing on this page has been verified on a device, and nothing in the guide's claims about Safari, VoiceOver, TalkBack, NVDA, Dynamic Type, Android font scale or Windows High Contrast has been observed. The list of what that covers is at the end. Menu names and gestures change between operating system versions; if a path below is gone, find it in the platform's own help.

Before you start

  • Get the page onto the device. npm run serve listens on 127.0.0.1 only, so a phone cannot reach it. Put docs/ on GitHub Pages (it is served as it is), or use a tunnel or any static host that answers on your network. A service worker and installing need HTTPS (or localhost); everything else works over plain http on a local network.
  • Choose the pages. Test the screens of your app. To test the guide itself, use the element pages named in each step; the keys and announcements they should give are on Patterns and in the Accessibility table of each element's page.
  • Record as you go. Device and OS version, browser, assistive technology, date, page, pass or fail, and what you heard or saw. A sheet is at the end.
  • Read "Pass looks like" as a description, not a script. Screen readers word things differently between versions and languages. What must be conveyed is the name, the role, the state and the position; the exact phrase is not the test.

iPhone: VoiceOver in Safari

Set up. Settings, Accessibility, VoiceOver; or set the Accessibility Shortcut (triple-click the side button) to VoiceOver so you can switch it on and off. Open the page in Safari. Learn five gestures: swipe right or left to move to the next or previous item; double-tap to activate; two-finger swipe up to read from the top; turn two fingers like a dial to change the rotor (Headings, Links, Form controls…) and swipe up or down to move by that unit; a two-finger scrub, a Z shape, to go back or close.

The VoiceOver script for an iPhone in Safari
StepDoPass looks like
1. Skip linkLoad the page and swipe right once.The first item is the skip link. Activating it moves to the main content; the next swipe is the first thing in <main>.
2. StructureSet the rotor to Headings and swipe down through the page; then to Landmarks.Headings come in order with no skipped level and each says what follows; there is a main landmark, a navigation landmark per nav with its own name.
3. Buttons and icon buttonsSwipe to a Button with text, one with only an icon, a toggle and a busy or unavailable one.Each says its name and that it is a button. The icon button says the action ("Add task"), not "plus". A toggle says it is on or off and keeps the same name in both. An unavailable button is still reachable and says so, with its reason readable.
4. LinksOpen the rotor to Links and swipe through them.Every link makes sense out of context. The current page is announced as current in a nav.
5. A formOn a Field page, swipe through a labelled field, a hint, then submit it empty.Label, role and hint are read with the field; a required field says so. After a failed submit focus moves to the error summary and its heading and entries are spoken; activating an entry focuses the field; an inline error is read when the field is focused.
6. A dialogOpen a Dialog; swipe around; then close it with the Z scrub and with its button.On opening, VoiceOver lands inside and announces its title as a dialog. Swiping never reaches the page behind. Closing returns to the control that opened it.
7. A toastTrigger a Toast, then one with an action, without touching the screen.The message is spoken once, without focus moving. An action toast says that the action is available and where to find it. An error is spoken at once.
8. Tabs and selectionOn Tabs, Chip and Segmented control: swipe and double-tap.A tab says its position ("1 of 3") and whether it is selected; activating one shows its panel. A filter chip says whether it is pressed; a choice says its position in the group. The announced state matches what you see.
9. A menu and a sheetOpen a Menu and a Sheet.The menu button says it is collapsed or expanded; items say "menu item" and their position; a checked item says so. A modal sheet traps the swipe inside it and has a Close you can reach.
10. Status and loadingTrigger a Skeleton load, a Progress bar and a filter that changes a count.The loaded content is announced once; progress announces milestones, not every tick; a changed count is spoken by the live region without moving focus.
11. Charts and tablesSwipe through a Bar chart, a Sparkline and a Table.A static chart is one image with a sentence that carries the point, and its data is a table you can reach. A table says its size; headers are read with cells; a sort says the new order.
12. Media and carouselsOpen a Carousel and a Marquee.Slides say "n of N". The carousel does not advance by itself. The ticker has a Pause you can reach before its moving text and is not read out as it scrolls.

Safari-specific things to look for. Reset lists keep their list role (role="list"), because Safari drops list semantics when list-style is none. The stretched link on a link card leaves a 2 px band at the very edge where a tap does nothing (Safari ignores overflow-clip-margin). Nothing zooms when a field is focused (inputs are 16 px). dvh full-height layouts do not hide content behind the toolbar. The inset focus ring in soft corners is clipped by the curve. All of these are expected from the source; none was seen.

For an app on the PWA page's recipe. In Safari: Share, Add to Home Screen. Then open it from the Home Screen.

The installed-app script for an iPhone
StepDoPass looks like
1. The icon and the nameLook at the Home Screen.The icon is the 180 px touch icon, not a screenshot; the name is the short name, not cut off.
2. The top strip and the page backgroundOpen the app in light, then dark (set the look in your settings or the system), then back to light.The strip above the page matches the canvas, with no band of another colour. If it does not update, note that (WebKit bug 301994: the colour is reported to change only on relaunch).
3. Safe areasHold the phone in portrait, then landscape, with a sticky bar and a dock on screen.Nothing is under the notch, the Dynamic Island or the home indicator; landscape side insets are respected; the bar and dock keep their controls reachable. 6. An updateDeploy a new version, open the app, leave and return to it.The "new version ready" toast appears; pressing Reload loads the new files exactly once.
7. The keyboardFocus a field near the bottom.The field stays visible above the keyboard and is not zoomed in on.

Dynamic Type and font scale

The guide sets every size in rem so that it follows the browser's text size. Whether the operating system's text size reaches a web page is exactly what nobody has checked: iOS Safari only follows Dynamic Type through a font: -apple-system-body rule that is in the base layer but unverified on a device, and Chrome on Android follows it only with <meta name="text-scale" content="scale"> (Chrome and Edge 146 and later), which is an optional head line. This is the first test to run.

The text size script for iPhone and Android
StepDoPass looks like
1. iPhone: does it follow?Settings, Accessibility, Display & Text Size, Larger Text. Turn on Larger Accessibility Sizes, drag the slider one notch at a time to the largest, and reload the page in Safari each time.Body text changes with the slider. If it does not, the Dynamic Type rule is not working for this page: note the iOS version and see Customize for the escape hatch. Repeat in the installed app.
2. iPhone: the largest sizeAt the largest size, walk the main screens.No text is cut off, nothing overlaps, no sideways scroll; buttons grow rather than clip; a sticky bar stays about two rows; the dock wraps to a second row; the focused control is not hidden behind a bar.
3. Android: does it follow?Settings, Accessibility (or Display), Font size to the largest, and Display size to the largest. Load the page with and without the text-scale meta.With the meta, text follows the setting in Chrome 146 or later; without it, only the browser's own text size applies. Note the versions. Layouts that still use px may scroll sideways with the meta on.
4. Android: the largest sizeWalk the main screens.The same as step 2.
5. Mid sizesRepeat at the size one notch above default.Nothing is clipped. Most bugs are not at the extreme.

400% zoom and text spacing

400% zoom. Open a desktop browser window 1280 px wide and 1024 px tall and zoom to 400%: the page now has 320 × 256 CSS pixels (WCAG 1.4.10). The 320 is the width that content must reflow to; the 256 is the height that content scrolling sideways must still fit. A window shorter than 1024 px gives an even shorter viewport, which is a harsher test. On an iPhone, pinch-zoom a page. The gate proves the 320 px case; the rest is yours.

The zoom script
StepDoPass looks like
1. 400% in a 1280 × 1024 windowZoom the page to 400% and scroll the whole page.There is no sideways scroll except inside a table, a code block or a scroller that has a label. No content or function is missing.
2. Only 256 px tallAt the same 400%, open a dialog, a sheet and a menu.Each fits or scrolls inside itself, and its close control is reachable. A floating dock stops floating on very short screens.
3. Pinch zoomOn a phone, pinch-zoom the page and a dialog.Zoom works everywhere; nothing blocks it (touch-action is limited to the control).

Text spacing (WCAG 1.4.12)

Paste this into the console on a page. It sets the four values of the criterion: line height 1.5, paragraph spacing 2× the font size, letter spacing 0.12em and word spacing 0.16em.

document.head.insertAdjacentHTML('beforeend',
  '<style id="ts">*{line-height:1.5!important;letter-spacing:.12em!important;word-spacing:.16em!important}p{margin-block-end:2em!important}</style>')

Pass looks like: no text is cut off, no two lines overlap, nothing scrolls sideways, every label is still whole. The snippet was run on the Button and Card pages and on this site's own pages at 390 px wide with every disclosure open, and the gate's clipped-text probe found nothing cut off and no sideways scroll. That is a start, not a test of your screens.

Windows High Contrast and forced colours

Set up. Settings, Accessibility, Contrast themes, pick a theme (the shortcut is Left Alt + Left Shift + Print Screen); or use forced colours in Firefox. Test in Edge or Chrome and in Firefox. The gate's forced-colours appearance emulates this in Chromium with the default system colours only.

The forced colours script
StepDoPass looks like
1. BordersLook at every card, control, input and tile.Every one has a visible edge, although fills and shadows are gone.
2. FocusTab through a page.The ring is a heavy outline in the theme's highlight colour, on every control.
3. StateLook at a selected tab, an on toggle, a current page, a checked box, a hovered and a pressed button.Each is told from its neighbours by a heavier frame, a mark or an outline, not by a fill. Selected does not shift the layout.
4. IconsLook at icons on a plain control and on a filled or selected one.Icons are drawn in the system text colour. Check that one on a highlighted fill is still visible.
5. Disabled and unavailableFind a disabled button and an aria-disabled one.Both read as unavailable (grey text, dashed edge) and differ from enabled ones.
6. Charts and patternsOpen a Donut and a Bar chart.Sectors and bars still differ by pattern.

Voice Control, Switch Control and keyboards

The script for voice, switch and keyboard input
StepDoPass looks like
1. Voice ControliPhone: Settings, Accessibility, Voice Control. Say "tap" and a button's visible label; then "show numbers".Saying the visible words works for every control that has visible text (WCAG 2.5.3). An icon-only control works by its aria-label or by number.
2. Switch Control or Switch AccessTurn on Switch Control (iPhone) or Switch Access (Android) with a single switch, and scan a page.Everything you can tap is reachable in a sensible order; nothing needs a drag or a pinch; the scan does not stall on a hidden control.
3. Keyboard only, desktopUnplug the mouse. Tab through a page, then use the keys in Patterns on each element.The skip link is first; order follows the visual order; nothing is a trap; Esc closes every overlay and returns focus to its trigger; focus is never hidden behind a sticky bar; the ring is visible on every control.
4. NVDA with Firefox or ChromeStart NVDA. Move through a page with the arrow keys, then with H for headings, D for landmarks and Tab for controls. Try a dialog and a tab list in both browse and focus mode.Widgets with a role (tabs, menu, dialog) announce their role, name and state, and their keys work; nothing important is read twice; live messages are spoken.

The script for operating system preferences and conditions
StepDoPass looks like
1. Reduce MotioniPhone: Accessibility, Motion, Reduce Motion. Android: Accessibility, Remove animations.Travel goes; fades stay; nothing is instant; spinners pulse. Pressing still gives feedback.

What is not verified

Everything on this page is unverified by definition. Specifically, these claims in the guide rest on source and on Chromium alone:

  • iOS: Dynamic Type through -apple-system-body; safe areas in an installed app and the status strip (WebKit 301994); apple-mobile-web-app-status-bar-style; the 16 px input rule; overflow-clip-margin on the link card; every VoiceOver announcement in the element tables.
  • Android: text-scale; font scale up to 200%; TalkBack announcements; the maskable icon on real launchers; WebAPK installs.
  • Windows: High Contrast themes beyond Chromium's emulation of the default colours; NVDA and JAWS announcements.
  • Browsers: Firefox and Safari for everything, including the features that need a 2024-era browser (container queries, :has(), @property, color-mix(), cascade layers, light-dark()).
  • People: nobody who uses a screen reader, a switch or Voice Control every day has used the guide.
