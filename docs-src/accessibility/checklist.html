Checklist

What every element and every screen must pass. First the definition of done for an element, then WCAG 2.2 row by row: the criterion, where the guide enforces it, and which check proves it. Rows marked manual have no automated check at all.

How to read this page

The target is WCAG 2.2 level AA as a hard floor, with a few AAA rules adopted because they cost little: 7:1 for body text (1.4.6), 44 px targets (2.5.5), a strong, unobscured focus ring (2.4.12, 2.4.13) and gentler motion (2.3.3). Each row says which level it is. This is a design target, not a conformance claim: nobody has audited it, and conformance is a property of whole pages, not of parts.

What the checks do and do not prove

Every automated check runs in Chromium on Linux against the guide's own pages. None has run in Safari or Firefox, on a phone, or with a screen reader. The checks prove the guide's parts; your app needs its own pass (Manual).

1.1.1 Non-text Content
Level A

Rule: Every image has alt (empty when decorative). Every icon-only control has an accessible name. Decorative icons are hidden.

Guide: .ic icons are aria-hidden masks, and the control carries the aria-label. A chart is one image with a sentence for a name and its data as a table one disclosure away (Bar chart, Donut, Sparkline).

  • lint
  • a11y gate
  • manual

Lint fails an <img> without alt, an icon span without aria-hidden and a <button> with no text and no label. axe: button-name, image-alt, svg-img-alt, link-name. Whether a name is the right name is manual.

1.2.1 / 1.2.2 Time-based media
Level A

Rule: Audio-only needs a transcript or an equivalent; video with speech needs captions.

Guide: The Player shows its Captions switch only when the media has a caption track. The captions and transcripts themselves are your content.

  • component spec
  • manual

The Player spec checks that the switch appears with a track and toggles it. Whether a recording has the right captions is manual.

1.2.3 / 1.2.4 / 1.2.5 Audio description; live captions
Level A / AA / AA

Rule: Prerecorded video has an audio description or a full text alternative (1.2.3), and at AA an audio description (1.2.5). Live video with sound has captions (1.2.4).

Guide: The Player has a Captions switch and nothing for an audio-description track or for live captions, so a video that needs one is your content: link a described version or a transcript beside the Player.

  • manual
1.3.1 Info and Relationships
Level A

Rule: Structure is in the markup: headings, lists, table headers and captions, labels, fieldset and legend.

Guide: Native elements first. Tables have a <caption> and real header cells (the Table uses th with scope). State is carried by ARIA attributes and native attributes, never by classes. Reset lists keep role="list", because Safari drops list semantics when list-style is none.

  • a11y gate
  • manual

axe: list, listitem, th-has-data-cells, td-headers-attr, empty-table-header, heading-order. Whether the structure makes sense is manual.

1.3.2 Meaningful Sequence
Level A

Rule: DOM order equals visual order. No CSS order or row-reverse that re-sequences interactive content.

Guide: The layout primitives never reorder. The Keypad keeps phone order (1-2-3 first) in the DOM, a Dialog's actions stack in DOM order, an Agenda's events are in time order whatever their lane, and the Gallery warns that dense packing can place a later tile beside an earlier one.

  • component spec
  • manual

Specs assert the order for the Keypad, Dialog and Agenda. No tool compares DOM order with visual order in general: tab through the screen and watch where focus goes.

1.3.3 Sensory Characteristics
Level A

Rule: Instructions never rely only on shape, colour, position or sound ("tap the green button on the right").

Guide: A writing rule for app authors.

  • manual
1.3.4 Orientation
Level AA

Rule: Do not lock portrait or landscape, in CSS, in script or with the manifest orientation member.

Guide: Nothing in the guide locks orientation. Full-height layouts use 100dvh and container queries, and the PWA manifest leaves orientation out.

  • manual

axe has an experimental rule for CSS orientation locks that the gate does not run. Read your manifest.

1.3.5 Identify Input Purpose
Level AA

Rule: Fields that collect data about the person carry a valid autocomplete token. Numeric fields use inputmode, not type="number" for things that are not quantities.

Guide: A rule for app authors: the guide cannot know what a field is for.

  • a11y gate
  • manual

axe autocomplete-valid checks tokens that are present; it cannot tell you one is missing.

1.4.1 Use of Color
Level A

Rule: Colour is never the only carrier of state, error, a link or a chart series.

Guide: Links are always underlined (a:not([class]) in the base layer). Selected and on states fill and double the frame, or add a tick. Status is an icon plus words. Tones carry rhythm, never meaning. The wire palette has no chroma, so it is a built-in test: if a screen still works in wire, colour is not carrying its meaning.

  • a11y gate
  • component spec
  • manual

axe link-in-text-block. Specs assert the second cue for selected chips, tabs, switches, swatches and bars. Everything else: flip to wire, then use the browser's vision-deficiency emulation.

1.4.2 Audio Control
Level A

Rule: Nothing plays sound by itself for more than 3 seconds without a control.

Guide: The Player never autoplays, and starting one pauses the others.

  • a11y gate
  • component spec
  • manual

axe no-autoplay-audio runs, but only has something to judge where an audio or video element exists.

1.4.3 Contrast (Minimum)
Level AA

Rule: Text 4.5:1; large text (24 px, or 18.66 px bold) 3:1.

Guide: Roles come in pairs with fixed lightness gaps, for every palette, theme and contrast mode. --ink and --ink-soft are 7:1, --ink-mute is the 4.5:1 floor, --ink-faint is 3:1 and never carries text that matters. Text on a tone reads --tone-ink and --tone-ink-soft, on the accent --on-accent. Text on a photo sits on a scrim or a solid plate.

  • contrast matrix
  • a11y gate
  • manual

The matrix resolves every pair through a real browser. The gate's axe color-contrast measures what is rendered on the docs pages (and is switched off under forced colours). Nothing detects opacity applied to text, and text over a real photo is unverified.

1.4.4 Resize Text
Level AA

Rule: 200% text without loss of content or function. No maximum-scale or user-scalable=no. No px font sizes.

Guide: Type, the space between blocks and the height of a control with a label are rem. The chrome around the words (insets, icon-only controls and their 44 px targets) stops at its 100% size, so large text gets the width (chrome caps). Layouts wrap and grow (minmax(), flex-wrap, container queries); a bar or a row of controls changes layout as a whole instead of wrapping raggedly (SG.fit). Words wrap between words with overflow-wrap: break-word rather than clipping.

  • lint
  • a11y gate
  • manual

Lint: a px font size or line height, an html font size other than 100%, a viewport that blocks zoom, overflow-wrap: anywhere. Gate: each page at 390 px with the root font size at 200% and every <details> open, failing on sideways scroll and on text cut off by a clipping frame. The largest iOS sizes are manual.

1.4.5 Images of Text
Level AA

Rule: Real text, not pictures of text.

Guide: Type is real text in a self-hosted font; symbols are masked icons.

  • manual
1.4.6 Contrast (Enhanced)
Level AAA (adopted)

Rule: Body text 7:1.

Guide: --ink reaches 7:1 on the canvas, paper, paper-2 and paper-3 in every palette, theme and contrast mode; --ink-soft on canvas, paper and paper-2 too. The measured minimums are in the table below.

  • contrast matrix
1.4.8 Visual Presentation
Level AAA (partly adopted)

Rule: Lines no longer than 80 characters; body line height at least 1.5.

Guide: --measure is 62ch and --lh-body is 1.5, which the body style uses.

  • manual
1.4.10 Reflow
Level AA

Rule: No two-dimensional scrolling at 320 CSS px wide (256 px tall for content that scrolls sideways). Data tables, code and maps may scroll.

Guide: Fluid grids (minmax(min(100%, n), 1fr)), wrapping rows, container queries inside elements, long words break. A Table scrolls inside a named keyboard-focusable region; a Toolbar scrolls sideways on purpose and has scroll buttons; Tabs scroll and keep every tab reachable by key.

  • a11y gate
  • manual

Gate: every page at 320 px wide with every <details> open; .table-wrap, .scroller and pre may scroll. The 256 px-tall case and 400% zoom are manual.

1.4.11 Non-text Contrast
Level AA

Rule: 3:1 for control boundaries, icons that carry meaning, focus rings and state indicators.

Guide: Frames are --line (ink: 7:1 or more). Quiet decoration is --line-soft (3:1). A tone's fill keeps 3:1 against its own card. The focus ring is --focus. Where a pale fill cannot separate itself (Cream's yellow), the 2px frame does.

  • contrast matrix
  • a11y gate
  • component spec
  • manual

Matrix: --line and --focus on every surface, --tone-fill against --tone-bg, the scrim. Gate: the ring measured against what it is drawn on, for every focusable. Specs: progress fill against its track, switch track and thumb in both states, the swatch check. That an element uses the right role is review.

1.4.12 Text Spacing
Level AA

Rule: Nothing is lost at line height 1.5, paragraph spacing 2x, letter spacing 0.12em and word spacing 0.16em.

Guide: Unitless line heights, no fixed-height text boxes, controls that grow.

  • lint
  • manual

Lint fails a px line height. The real test is the snippet on the Manual page; the gate's 200% text pass finds clipped text but is not the same test.

1.4.13 Content on Hover or Focus
Level AA

Rule: Anything that appears on hover or focus can be dismissed (Esc), can be hovered, and stays until dismissed. Nothing essential appears only on hover.

Guide: The Tooltip is hoverable, dismissible and persistent, and is never a control's only name. Hover styling sits inside @media (hover: hover). Overlays are built on <dialog> and popover.

  • lint
  • component spec
  • manual

Lint warns on :hover outside (hover: hover) in an element's CSS. The Tooltip spec covers Esc, hoverable and persistent.

Operable

People can operate it with any input: keyboard, touch, voice, switch. Nothing traps, nothing is hidden, nothing moves without a way to stop it.

Operable: criterion, rule and how the guide meets it, and how it is checked
CriterionRule, and how the guide meets itChecked by
2.1.1 Keyboard
Level A

Rule: Everything works with a keyboard alone, following the APG pattern for the widget.

Guide: Native elements first. Roving tabindex for tabs, radio groups, toolbars, menus and grids. Every gesture has a key or a button. The pattern and keys of every element are on Patterns.

  • component spec
  • a11y gate
  • manual

A spec per element presses real keys and asserts focus and ARIA state. The gate tabs each page (up to 120 stops) to show controls can be reached, not that they work.

2.1.2 No Keyboard Trap
Level A

Rule: Focus can always leave. Esc closes an overlay and focus returns to what opened it.

Guide: Overlays are native <dialog> and popover. A modal traps focus inside on purpose, and Esc and a visible button always leave; a popover closes when focus tabs out of it.

  • component spec
  • manual

Specs for Dialog, Sheet, Popover, Menu and Tooltip cover Tab, Esc and focus return. The gate does not detect traps.

2.1.4 Character Key Shortcuts
Level A

Rule: No single-character shortcuts unless they can be turned off or only work while a widget has focus.

Guide: The only global key is F8, which jumps to a Toast; it is not a character key. Type-ahead and the Keypad's digit keys work only while focus is inside the widget.

  • manual
2.2.1 Timing Adjustable
Level A

Rule: Time limits can be turned off, adjusted or extended. Nothing that holds an action, an error or key data disappears by itself.

Guide: A Toast stays at least 6 seconds, longer for a longer message, and pauses on hover, focus, a held touch and a hidden tab. A toast with an action, and every error, never closes itself.

  • component spec
  • manual
2.2.2 Pause, Stop, Hide
Level A

Rule: Anything that moves, blinks or scrolls by itself for more than 5 seconds has a visible pause control. Pausing only on hover or focus does not count.

Guide: A Marquee has a Pause button before the moving text and stays still without one. A Carousel does not advance until Play is pressed and stops for good when focus enters it. A spinner belongs to a busy state, not to the page.

  • component spec
  • manual
2.3.1 Three Flashes
Level A

Rule: Nothing flashes more than 3 times per second.

Guide: Elements animate only transform, opacity and the two registered numbers. The fastest loops are an 800 ms spin and a 1.4 s pulse; the skeleton's dip is slow, shallow and stepped.

  • manual

Review only. No tool here measures flashes.

2.3.3 Animation from Interactions
Level AAA (adopted)

Rule: Motion caused by interaction can be turned off. Reduced motion means a fade, not a jump cut.

Guide: --move goes to 0 under prefers-reduced-motion or data-motion="reduced" and every element multiplies its travel by it; a spinner becomes a pulse; durations are never zero. data-motion="full" overrides a device request for someone who wants motion.

  • lint
  • component spec
  • manual

Lint keeps the media-query block and the attribute block identical. Specs emulate reduced motion. Nothing watches every animation in every element.

2.4.1 Bypass Blocks
Level A

Rule: A skip link is the first Tab stop and lands in <main>. Landmarks are used.

Guide: .skip-link in the base layer, shown on focus. The docs layout uses it, and the minimal file shows it in an app.

  • a11y gate
  • manual

axe: bypass, skip-link, region, landmark-*. Your app's own shell is yours to check.

2.4.2 Page Titled
Level A

Rule: Every screen has a unique, meaningful <title>. A single-page app updates it when the route changes.

Guide: The docs layout sets it per page.

  • a11y gate
  • manual

axe document-title. Route changes in an app are manual.

2.4.3 Focus Order
Level A

Rule: Focus follows the visual order. No tabindex above 0.

Guide: DOM order is visual order. tabindex="-1" is used for things focus is sent to (<main>, the error summary) and for the inactive items of a roving group.

  • lint
  • a11y gate
  • component spec
  • manual

Lint fails a positive tabindex; axe tabindex. Specs assert tab order for the Appbar, Input, Pagination and others.

2.4.4 / 2.4.6 Link Purpose; Headings and Labels
Level A / AA

Rule: Link text makes sense out of context. Headings and labels describe their content.

Guide: A writing rule. The App bar requires a heading and names its back link after where it goes; a Pagination's page asks for a nav named after what it pages.

  • a11y gate
  • component spec
  • manual

axe: link-name, empty-heading, heading-order. Whether the words are good is manual.

2.4.5 Multiple Ways
Level AA

Rule: More than one way to find a screen in a set of screens (a menu, a search, links between related screens), except a screen that is a step in a process.

Guide: An app rule. The guide supplies the parts: the App bar with its search bar, the Dock, the Breadcrumb and Pagination.

  • manual
2.4.7 Focus Visible
Level AA

Rule: Every focusable control shows a visible indicator.

Guide: One ring: var(--ring) solid var(--focus) (3px) at --ring-offset (3px), plus a paper halo so it shows on any background. Inside something that clips, --ring-gap moves it in. On a tone or an ink surface the ring follows the surface, because an ink ring on an ink card vanishes. Forced colours get a 4px Highlight outline.

  • lint
  • contrast matrix
  • a11y gate

Lint: outline: none without a replacement. Matrix: --focus on every surface and on every tone. Gate: every control reached by Tab has an outline or a shadow and its ring is at least 3:1 against what it is drawn on, in all five appearances.

2.4.11 / 2.4.12 Focus Not Obscured
Level AA / AAA (adopted)

Rule: A focused control is never hidden behind a sticky bar or dock (AAA: not even partly).

Guide: html gets scroll-padding from --appbar-h, --dock-h and the bottom safe-area inset. A sticky bar or dock publishes those variables; a persistent Sheet keeps a focused page control clear of itself.

  • a11y gate
  • component spec
  • manual

The gate checks that the centre of each focused control is not covered. Specs for the Appbar, Dock and Sheet tab through a scrolling list. Partial overlap needs a scroll-and-Tab pass by hand.

2.4.13 Focus Appearance
Level AAA (adopted)

Rule: An indicator at least 2 px thick around the control, with 3:1 between focused and unfocused pixels.

Guide: The ring is 3px and drawn in ink, measured at 11.20:1 or more against the four surfaces.

  • contrast matrix
  • a11y gate

The ring's colour against its background is measured. The change between focused and unfocused pixels is not.

2.5.1 Pointer Gestures
Level A

Rule: Swipes, pinches and other path gestures have a single-tap alternative.

Guide: A carousel swipes and has Previous and Next; a toolbar swipes and has scroll buttons; a calendar pages with buttons. Gestures are an enhancement, never the only way.

  • component spec
  • manual
2.5.2 Pointer Cancellation
Level A

Rule: Actions fire on release (click), not on press, so dragging away cancels.

Guide: Native buttons and links. Hold-to-repeat (the Keypad's delete, the Stepper) repeats only after a delay, a tap is exactly one step, and a hold that ends off the button leaves no swallowed click.

  • component spec
  • manual
2.5.3 Label in Name
Level A

Rule: The accessible name contains the visible text, starting with it.

Guide: Visible text is the name; aria-label is for icon-only controls. A toolbar tool is named by its visible label, and a swatch by its visible word, so a person can say it.

  • component spec
  • manual

axe has an experimental rule for this that the gate does not run. Voice Control ("tap Save") is the real test; see Manual.

2.5.4 Motion Actuation
Level A

Rule: Shake, tilt and similar triggers also have a button and can be turned off.

Guide: The guide has none.

  • manual
2.5.5 Target Size (Enhanced)
Level AAA (adopted)

Rule: 44 x 44 CSS px, with at least 8 px between neighbouring targets.

Guide: --hit is 2.75rem and grows with a control's label; an icon-only control's target is --chrome-hit, 44 px at every text size. A smaller drawing extends its hit area with the ::after pattern from .btn. Rows in a List touch, so there is no gap to mis-hit.

  • lint
  • a11y gate
  • component spec

Lint warns on a control drawn under 44px. The gate warns under 44 counting invisible hit areas, and skips inline links in sentences. Specs measure Keypad, Segmented and others; the 8 px gap is asserted in specs, not by the gate.

2.5.7 Dragging Movements
Level AA

Rule: Every drag has a single-pointer alternative. Keyboard support does not count.

Guide: Slider, Scrubber and Timeline have nudge and step buttons and click-to-jump; a Sheet's handle is a button that toggles full height; the Stepper steps by tap; Carousel and Toolbar have buttons.

  • component spec
  • manual
2.5.8 Target Size (Minimum)
Level AA

Rule: At least 24 x 24 CSS px, unless spaced, equivalent, inline or a native control.

Guide: Nothing is smaller than its 44 px hit area.

  • a11y gate

The gate fails under 24 px, and axe target-size runs as well.

4.1.3 Status Messages
Level AA

Rule: Results and errors are announced without moving focus: SG.announce() (polite) or role="alert" (assertive, rarely). Live regions exist before their text changes.

Guide: SG.announce writes into a polite and an assertive region, clearing the text and setting it on the next frame so a repeated message is spoken again. A Toast announces through its own persistent regions and is never inside a live region itself.

  • manual

Before you ship a screen

  1. Run npm run build && npm test in the guide, and your own app's axe pass in your browser's DevTools.
  2. Walk the manual rows above for what the screen contains: tab through it, zoom to 200%, open it at 320 px, switch to dark, to wire and to more contrast.
  3. Read every label, error and empty state out loud. If it sounds like a landing page, rewrite it.
  4. On a real phone, run the scripts for the platform you ship on.

The same checks apply to a new element; the pipeline is in CLAUDE.md, and the definition of done is at the top of this page.
