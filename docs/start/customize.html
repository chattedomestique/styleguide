Customize

Make the guide yours without editing it. Your CSS lives in your app, the guide's files stay as they are, and an upgrade is a file swap.

How overrides work: cascade layers

Every rule in the guide sits in one of seven layers, weakest first: sg.reset, sg.tokens, sg.base, sg.layout, sg.wire, sg.components, sg.utilities. CSS that is not in any layer beats CSS in every layer, whatever its specificity and wherever it comes in the file. So a plain rule in your stylesheet wins, with no !important and no selector fight.

Two ways to write your CSS, in one file linked after styleguide.css:

/* Plain, unlayered CSS beats every sg.* layer, at any specificity. */
.btn.cta {
  min-inline-size: min(11rem, 100%);
  font-weight: 800;
}

/* Or keep your own CSS in a named layer. Name it AFTER the guide's stylesheet has been read,
   so that "app" sits above the guide's layers. */
@layer sg.reset, sg.tokens, sg.base, sg.layout, sg.wire, sg.components, sg.utilities, app;
@layer app {
  .btn.cta { min-inline-size: min(11rem, 100%); }
}
  • Unlayered is the simplest and the strongest. It beat the guide even as :where(.cta), at zero specificity (checked).
  • A named layer lets you order your own CSS into parts. A new layer that first appears after the guide's stylesheet is above it. If @layer app appears before the guide in the document, app becomes the weakest layer and the guide wins (checked: the override did nothing).
  • Custom properties you set outside any layer win the same way. That is what you want for a font, and what you do not want for colour knobs (see below).

The token contract

Everything is a custom property, in four tiers. Know which one you are touching.

The four kinds of custom property and how to treat each
TierExamplesWhat to do
Roles--canvas --paper --ink --ink-soft --line --focus --accent --on-accent --ok-ink --scrim; --tone-bg --tone-ink --tone-fill; the surface contract --surface-bg --surface-ink --surface-ink-softRead them in your own components and let the guide compute them. Do not redefine one half of a pair. --tone-* are readable only on the toned element itself.
Scales--space-1 to --space-9, --text-xs to --text-4xl, --type-body and its siblings, --bw, --bw-thin, --radius-card --radius-tile --radius-ctl --radius-pill, --hit, --ctl, --dur-hover, --ease-out, --moveRead them. Change a scale only through its documented switch: the font through --font-sans (below), corners through data-corners, motion through data-motion.
Knobs--k-* (lightness, chroma, hue), --tone-h-1 to --tone-h-6, --tone-c-1 to --tone-c-6, --hue-ok and its siblingsSet them in a palette block (next sections). They are plain numbers, and contrast is protected because lightness gaps stay fixed while you change hue and chroma.
PrivateAnything that starts with --_, such as --_h or --_rest-bg in the buttonNever read or set. They are a component's internals and change in any release.

Colour is built in three steps: knobs become roles, and components read roles. Override at the lowest step that does the job and you keep the guarantees above it. The Colour page explains the construction; Upgrade lists what counts as public API.

Make a palette

A palette is one block that sets knobs. Name it, and select it with data-palette. This one, clay, is a warm terracotta, written the way an app would write it:

/* my-app.css, linked AFTER styleguide.css.
   Inside the guide's own token layer, so the higher-contrast knobs (which are more specific)
   still win when someone asks for more contrast. Written unlayered, this block would beat them. */
@layer sg.tokens {
  [data-palette="clay"] {
    /* greys: warm, with a little tint in the canvas */
    --k-neutral-h: 50;
    --k-neutral-c: 0.012;
    --k-canvas-c-l: 0.03;
    --k-canvas-c-d: 0.02;

    /* accent: the hue and vividness are yours; the lightness gaps are what keep contrast */
    --k-accent-h: 45;
    --k-accent-c: 0.13;
    --k-accent-fill-l: 0.48;    --k-accent-fill-d: 0.76;
    --k-on-accent-l: 0.99;      --k-on-accent-d: 0.18;
    --k-accent-ink-l: 0.45;     --k-accent-ink-d: 0.82;
    --k-accent-soft-l: 0.92;    --k-accent-soft-d: 0.3;
    --k-on-accent-soft-l: 0.3;  --k-on-accent-soft-d: 0.94;

    /* six tone slots: a hue and a vividness each (the lightness is shared, and is what carries contrast) */
    --tone-h-1: 45;  --tone-c-1: 0.13;
    --tone-h-2: 75;  --tone-c-2: 0.12;
    --tone-h-3: 20;  --tone-c-3: 0.13;
    --tone-h-4: 130; --tone-c-4: 0.10;
    --tone-h-5: 230; --tone-c-5: 0.08;
    --tone-h-6: 340; --tone-c-6: 0.09;
  }
}
  1. Pick the greys. --k-neutral-h tints every neutral a little; --k-canvas-c-l and -d tint the canvas a little more.
  2. Pick the accent. Hue and chroma are free. Copy the lightness values from the Mint block (a deep accent with a light label) or from Cream (a pale accent with a dark label) and do not move them.
  3. Point the six tone slots at six hues. Tones carry rhythm, never meaning, so the order is yours.
  4. Write it inside @layer sg.tokens in a file linked after the guide, and name the palette rather than writing on :root (why).
  5. Select it with <html data-palette="clay">, or on any region.

These are live islands: the block above is loaded on this page. Theme, palette, corners and contrast work on any element. data-motion is the exception: it only works on <html>, so set it there.

Write it inside the guide's layer, and not on :root

Two habits break contrast without any warning.

  1. Unlayered knobs defeat the higher-contrast block. The knobs for prefers-contrast: more live inside sg.tokens and are more specific than [data-palette], so within that layer they win. An unlayered [data-palette="clay"] beats all of it, and people who asked for more contrast keep your normal accent. The same clay block, written unlayered, failed the matrix: text on the accent fill measured 6.53:1 where 7:1 is required. Inside @layer sg.tokens { } it passes. The same goes for the reduced-motion knobs.
  2. Knobs on :root beat every palette, including the one a person picks in your settings: an unlayered :root { --k-accent-h: 30 } turned a mint page's accent red (checked). Give your look a palette name instead.
/* Avoid: beats every palette, including the ones your users pick. */
:root { --k-accent-h: 30; }
A palette on an island gets the higher-contrast boost too

The guide repeats its higher-contrast knobs for every [data-palette] inside a higher-contrast page, so a region with its own palette still collapses its accent to ink. Checked: text on the accent measured 18.39:1 for periwinkle and 18.49:1 for clay inside a data-contrast="more" page, where an island once kept 6.60:1. That holds for a palette written inside @layer sg.tokens, as above. Written unlayered, a palette beats the repeat (see the first habit above).

Check the contrast of your palette

The matrix in tests/contrast.mjs resolves every role pair through a real browser for every palette, theme and contrast mode. Until your palette is listed there, nobody has measured it.

  1. If the palette lives in the guide (best when more than one app will use it): paste the block into src/tokens/40-palettes.css, add the name to PALETTES at the top of tests/contrast.mjs and to the docs switcher, then npm run build && npm run test:contrast.
  2. If it lives in your app: link your file in tests/fixtures/contrast.html after the guide's link (the test serves the repository root, so the file must be reachable from it), add the name to PALETTES, and run the same commands.

Both routes were run with the clay block above in a scratch copy of the repository. Clay is a seventh palette, so the matrix runs 28 combinations instead of 24, and 26 island ones instead of 22. It passes:

All 12150 contrast checks passed across 28 theme/contrast/palette combinations, plus 26 island combinations.

A failure names the pair, the worst case and the colours. This is clay with --k-accent-fill-l raised from 0.48 to 0.62, a "dead zone" where neither white nor black text reaches 4.5:1:

1 of 12150 checks FAILED, in 1 distinct pairs:

  x --on-accent on --accent (text on accent fill) needs 4.5
      worst 3.62:1 in light/off/clay (#fff8f1 on #c56a3e); 1 combos, e.g. light/off/clay

Fix it by moving the accent's lightness, not the label's. Testing explains the matrix and how to add a pair. Then set the two theme-color metas to your canvas colours (Install). To change a built-in palette rather than add one, edit 40-palettes.css in a fork; the Colour page walks through it.

Tone hues

Tones are the owner's API: data-tone="1" to "6", "ink", and the four statuses "ok", "warn", "bad", "info", on any element. A palette decides what the six slots look like, by setting --tone-h-N and --tone-c-N. The text on a tone is 7:1 by construction because the tone's lightness is shared, so you can point a slot at any hue (clay does) and the contrast holds.

  • To recolour a slot for your app, put it in your palette block (above), not on :root: a :root rule beats every palette, including the one a person picks in your settings, so the six slots would look the same in all of them (checked: an unlayered :root { --tone-h-1: 200 } won in all six).
  • Status hues (--hue-ok and friends) are shared by every palette. Change them only if the default red, amber, green and blue do not suit you, and keep the icon and words with every status.
  • Tones carry rhythm, never meaning. Six slots across a grid of decks make it easy to scan; a tone alone must never say "error" or "done".

Shape: square or soft

Everything that is not a circle or a pill reads three radius roles, and data-corners sets all three. Pills and circles stay round, lines stay 2px and 1px, and no component changes.

What data-corners changes
Rolesquare (default)softUsed by
--radius-card024pxthe card frame
--radius-tile012pxicon tiles, media
--radius-ctl06pxthe small square control

Square

Soft

  • Choose square if the app should look like the owner's sheet: hard edges, poster type, frames you can see. It is the default because the owner's committed CSS is square.
  • Choose soft if friendlier edges suit the app. The same tests pass either way, and the accessibility gate runs a soft appearance on every page.
  • Commit to one: write the attribute on <html>, or offer it in your settings (SG.prefs.set('corners', 'soft')). To change the default for every app that uses your fork, edit the default block in src/tokens/30-corners.css; nothing in src/components/ changes.
  • Limits: the notch card stays square in both, because its cut is its shape gesture (one per card: round it or notch it). In soft corners an inset focus ring can be partly clipped by the radius (a documented limit in the audit).
  • A third style is one block that sets the same three roles, for example [data-corners="pebble"] { --radius-card: 1rem; --radius-tile: 0.5rem; --radius-ctl: 0.25rem; }. Do not add a fourth radius: the guide's lint fails it, and the point of the roles is that a card, a tile and a control always agree.

Changing the font

The font is one token, --font-sans, and every type style reads it (--type-body, --type-title and the rest are whole font shorthands that end in it). Set it on :root:

/* Set it on :root. The type styles are resolved there, so a font set on a nested
   element would not reach .t-body, .btn and friends. */
:root {
  --font-sans: system-ui, sans-serif;
}

Checked: with this rule body text, display text and buttons all resolved to the system stack, and no font file was requested. The same rule on a nested element changed nothing for .t-body or .btn inside it. Remove the font preload from your head too, or it downloads for nothing. For a web font of your own, declare its face and set the token:

@font-face {
  font-family: "Plus Jakarta Sans";
  src: url("fonts/plus-jakarta-sans-latin-wght-normal.woff2") format("woff2");
  font-weight: 200 800;
  font-style: normal;
  font-display: swap;
}
:root {
  --font-sans: "Plus Jakarta Sans", system-ui, sans-serif;
}
  • Archivo has a width axis and the styles use it. The display line is expanded, labels are condensed, and the figure is semi-expanded (font-stretch keywords). A font with no width axis ignores them: posters and labels lose their shape, and condensed labels take more room. That is a design change, not a bug.
  • It needs tabular numerals (tnum), or money and time columns will not line up.
  • It needs the true minus U+2212; the guide formats negative numbers with it. If the font lacks it, that one glyph falls back to another font.
  • Weights 400 to 900 are used. A missing weight is faked by the browser and looks smeared.
  • Keep form fields at 16 px or more (--text-md): smaller makes iOS zoom in on focus.
  • Not in the bundled font: Cyrillic, Greek, Arabic, Hebrew, Indic and CJK scripts, and arrows, checks and ≤ ≥. They fall back glyph by glyph to the next family in the stack. Draw symbols as icons.

Adding your own element

An app-specific element can live in your CSS and still obey the rules. They are the ones the guide's elements follow, and src/components/button.css is the file to copy:

  • Colours come only from roles; shape from the radius roles and --bw / --bw-thin; space and type from their scales. No hex, no px font sizes.
  • State comes from ARIA and native attributes (aria-current, aria-pressed, :disabled), never from classes that assistive technology cannot see.
  • A second cue besides colour for every state, and a real border so forced-colours mode keeps the edge.
  • A 44 px hit area with 8 px between neighbours, using the ::after pattern from .btn.
  • Words grow with the reader's text size; the chrome around them does not. Padding and the gaps inside a control use the --chrome-* steps (chrome caps).
  • Hover only inside @media (hover: hover). Never outline: none without a replacement. Travel multiplied by --move.
  • A pressable thing sets --lift and --fill for every state and declares both at rest, so it cannot inherit a hovered parent's. An action fills on hover, as the link below does; a thing you select (a chip, a tab, a toggle) only rises on hover and keeps the fill for selected (the selection recipe).

A small example that follows all of them. It is a pill link, which <a class="btn"> already gives you, so in a real app you would use that. It is written out because it is short and shows every rule; write your own only for a shape the guide does not have. This CSS is loaded on this page, so the link below is the real thing:

/* A streak link for a profile header. Roles only, no literals. It copies the structure of
   button.css: two numbers for every state, a hit area, the focus shadow, travel times --move. */
.streak {
  --lift: 0;   /* a pressable thing declares both numbers, or it inherits a hovered parent's */
  --fill: 0;
  position: relative;               /* anchors the hit area below */
  display: inline-flex;
  align-items: center;
  gap: var(--chrome-2);             /* insets and gaps inside a control are chrome: they stop at 100% */
  min-block-size: var(--ctl-sm);    /* drawn at 36px; the hit area below is 44px */
  padding-inline: var(--chrome-4);
  color: color-mix(in srgb, var(--on-accent) calc(var(--fill) * 100%), var(--ink));
  background: color-mix(in srgb, var(--accent) calc(var(--fill) * 100%), var(--paper));
  border: var(--bw) solid var(--line);          /* a real border: forced colours deletes fills and shadows */
  border-radius: var(--radius-pill);
  box-shadow: calc(var(--lift) * var(--space-1)) calc(var(--lift) * var(--space-1)) 0 0 var(--line);
  font: var(--type-ctl);
  text-decoration: none;
  transform: translate(calc(var(--lift) * var(--space-1) / -2 * var(--move)), calc(var(--lift) * var(--space-1) / -2 * var(--move)));
  transition: --lift var(--dur-hover) var(--ease-out), --fill var(--dur-hover) var(--ease-out);
}

/* same 44px hit area as .btn */
.streak::after {
  content: "";
  position: absolute;
  inset-block: min(0px, calc((100% - var(--hit)) / 2));
  inset-inline: min(0px, calc((100% - var(--hit)) / 2));
}

/* hover only where a pointer can hover; keyboard focus lifts the same way */
@media (hover: hover) {
  .streak:hover { --lift: 1; --fill: 1; }
}
.streak:focus-visible {
  --lift: 1;
  --fill: 1;
  box-shadow: var(--focus-shadow), calc(var(--lift) * var(--space-1)) calc(var(--lift) * var(--space-1)) 0 0 var(--line);
}
.streak:active { --lift: 0; --fill: 1; transition-duration: var(--dur-press); }

/* forced colours: fills and shadows vanish, so raised gets a heavier line */
@media (forced-colors: active) {
  .streak { border-color: ButtonText; }
  .streak:is(:hover, :focus-visible) { outline: var(--bw-heavy) solid Highlight; }
}
12-day streak

If an element will be used by a second app, add it to the guide instead, so it gets a page, a keyboard spec and the accessibility gate (the pipeline is in CLAUDE.md). Do not rebuild what exists: a button that goes somewhere is an <a class="btn">, a row in a list is a Card row.

What not to override

Things to leave alone, why, and what to do instead
Leave aloneBecauseInstead
The focus ring: outline and --focus-shadow on :focus-visible, --ring, --ring-offset, --focusThe ring and its paper halo are measured against every surface and tone; the accessibility gate measures the ring of every focusable (WCAG 2.4.7, 2.4.11). A new colour voids that measurement.If an element has its own box-shadow, write box-shadow: var(--focus-shadow), <yours> in its :focus-visible rule. Inside something that clips, set --ring-gap: var(--ring-offset-in).
--hit, --ctl-sm --ctl --ctl-lg, the hit-area ::after44 px is the default on purpose. The accessibility gate warns under 44 and fails under 24 (WCAG 2.5.8, 2.5.5).Make things look smaller with padding, never with a smaller hit area.
