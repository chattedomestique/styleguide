Start

Style guide

The buttons, forms, cards and bars of an app, written once for every app you build. Plain HTML, CSS and a little JavaScript: an app copies a few files and needs no build step.

Start here

  1. InstallCopy three files, add four lines to your head, write a button.
  2. Make it yoursPick a palette, corners and theme with attributes, or add your own palette.
  3. Learn the foundationsColour, type, shape, tones and how things move.
  4. Pick your elementsEvery element has a live demo, every state, the keyboard and screen-reader behaviour, and the tokens it uses.
  5. Check your workThe WCAG 2.2 checklist, what the tests prove and what only a person can.

Open Appearance at the top right and change the theme, palette, corners, contrast or motion. Every page on this site, including this one, updates live.

The seven rules

  1. Two line weights. 2px frames what you press or what contains. 1px only divides. 4px exists for forced colours and nothing else.
  2. Flat. No gradients, no blur, no glass. A shadow is hard-edged and means "you can press this".
  3. Rectangles hold, circles act. Containers are rectangles (square or soft). Buttons, handles and action slots are circles or pills.
  4. Uppercase is structure. Bar labels, index numbers, the display line. Everything you read is sentence case.
  5. Say something real. No lorem ipsum, no "John Doe", no "seamless". Copy comes from the app.
  6. Colour is a swap. Components read roles. Only src/tokens contains a colour literal.
  7. No decoration. If it carries no information and offers no action, it goes.

Use it in an app

<html lang="en" data-palette="mint" data-corners="soft">
  <link rel="stylesheet" href="styleguide.css">
  <button class="btn" data-variant="primary">Add funds</button>

The whole setup, with the PWA parts, is on the Install page.

What is here

Foundations

  • ColourKnobs, roles and components: every colour pair keeps a fixed lightness gap, so contrast is decided before a hue is picked.
  • TonesSix slots, an ink tone, four status tones and a bold emphasis: five guaranteed-contrast roles per element, from one hue, for rhythm and never for meaning.
  • TypographyOne family, three widths: Archivo Variable, the six type styles, the rem size scale, container-relative sizes, numerals, case and wrapping.
  • SpaceThe 4px grid in rem, chrome caps (what grows with the reader's text and what stops), gutters and measure, 44px hit targets and the hit-area technique, and the z-index layers.
  • ShapeTwo line weights, three radius roles and the pill: square or soft with one attribute, and nothing decorative.
  • InteractionTwo numbers, lift and fill, describe every state of everything you can press, for actions and for selection controls: the hard-shadow rule, pressed, selected, disabled, busy, focus and forced colours.
  • MotionGate 4: four durations and three easings, one number that turns travel into a fade, and reduced motion that is gentler rather than instant.
  • IconsCSS-mask icons drawn with the frame's 2px line: the five the owner drew, about 150 more from Lucide, names, sizes, colour, how to add one, and the full gallery.
  • LayoutThe app shell, stack, cluster, split, grid, bleed and scroller, container queries before media queries, sticky chrome, safe areas and rows that never wrap raggedly: small primitives that reflow at 320px and 200% text.

Actions

  • ButtonPills and circles you press: secondary, primary, tone, icon-only.

Forms

  • FieldThe wrapper around every form control: label, hint, error, required wording, counter, groups and the error summary.
  • InputText, email, password, number, search, date and amount fields, and the auto-growing textarea, on native elements.
  • SelectA styled native select: our closed control, the browser's own picker.
  • ChoiceCheckboxes, radios and selectable cards: native inputs with a 44 px hit area, groups and an indeterminate state.
  • SwitchAn on/off setting that takes effect at once: a real checkbox with role=switch, a pill track and a circle thumb.
  • SliderA native range input with a filled track, a live readout in units, tick marks and - / + nudge buttons.
  • StepperA quantity control: a number field between two circle buttons, with limits, long-press repeat and announcements.
  • KeypadA numeric keypad for entering an amount: round 3 x 4 keys, a live amount display, hardware keys and a confirm button.

Selection and navigation

  • TabsSwitch between panels on the same screen: pill or underline, scrolling, vertical. Roving tabindex, automatic or manual activation.
  • ChipInteractive pills: filters that toggle, choices that exclude each other, removable inputs and a +N disclosure.
  • Segmented controlPick one of two to four equal options: a pill track with native radios. Sizes, icons, a sliding thumb, tone.
  • App barThe top bar of a screen: a heading, a named back control, one or two actions. Standard, greeting, editor and search; ink or tonal; sticky and safe-area aware.
  • DockBottom navigation: a floating pill or a full-width bar, icon and word per destination, a current-page fill, an optional round centre action.
  • BreadcrumbThe trail from the top of a hierarchy to this page, with a way up at every step. A labelled nav, an ordered list, aria-current on the last item.
  • PaginationMove through a long list: Previous, a few numbered pages, Next. Real links, a filled current page, and a short form that fits a 320px phone.

Surfaces

  • CardA frame with slots that holds one idea: ten variants, six states, two grids. From the owner's Flashcards style sheet v0.1.
  • TagA small pill that names a kind, a status or a priority. Read, never pressed. Replaces the wireframe .wf-pill.
  • AvatarA person as a circle: a photo or their initials, five sizes, a presence dot that is never colour alone, and the overlapping stack.
  • DividerA line that separates, with an optional label: the plain rule, the framed section break, the labelled "or", and the vertical rule.
  • AccordionSections that fold away, built on native details and summary: one open at a time or many, as rows or as Card panels.
  • TileThe square quick action: an icon and a name on a field of colour, pressable, with an optional count. Plus a caption variant for decks and photos.
  • ListRuled rows for settings, history and decks, with a leading slot and a trailing value, tag, chevron or control; and the key / value grid.
  • StatA recipe, not a component: how the Card stat, Tags, a List and Avatars compose a dashboard. No new CSS.

Overlays and feedback

  • DialogA modal box that stops the flow for one decision, on the native dialog element: confirm, destructive alert, form. A card in the top layer.
  • SheetA panel that slides up from the bottom on a phone and docks to the side on a wide screen, with a handle that is also a button. Modal or persistent.
  • MenuA button that opens a list of commands, to the WAI-ARIA menu button pattern, with an action-sheet presentation for phones.
  • PopoverA small non-modal card next to the control that opened it: help, a few options. Native popover attribute, anchored, light dismiss.
  • TooltipA few words on hover and keyboard focus: hoverable, dismissible with Esc, persistent, and never the only name of a control.
  • AlertAn inline banner, built on Card, for information, success, warning and errors that stays until it is fixed or dismissed.
  • ToastA short, passing confirmation above the dock that never takes focus, pauses while you read it, and keeps errors until you dismiss them.
  • ProgressLinear, indeterminate, ring and step progress, plus the meter that Card's stat uses: always with the value as text.
  • SpinnerA working indicator with a real label, a 300 ms delay, and a pulse instead of a spin when motion is reduced.
  • SkeletonFlat placeholders that mirror the layout while content loads: shown only after 300 ms, a stepped pulse, and still when motion is reduced.
  • Empty stateWhat a view shows when there is nothing yet, nothing found, something broke or there is no connection: an icon, a sentence, one fix.
  • MarqueeA scrolling ticker strip with an always-visible Pause/Play button; static when paused or when motion is reduced.

Data

  • TableA real table in a scroll region: sticky first column, sortable headers, optional row selection, numbers that line up.
  • Bar chartCompare a few values by length: tone plus pattern, printed values, a selected bar, and the data one disclosure away as a table.
  • SparklineA tiny inline trend with a text alternative: one 2px line and an end dot, no axes, never the only way to read the numbers.
  • Donut chartParts of a whole, a handful of them: tone plus pattern sectors, the total in the hole, and a legend whose labels carry the values.
  • LegendThe key to a chart: a swatch that is a tone and a pattern, the name in words, and the number when the chart does not print it.
  • CalendarA month grid or a week strip with arrow-key navigation, today and chosen days marked by shape, event markers that are also text, and Intl names.
  • AgendaWhat is on, when: tonal day cards with hour columns, and a one-day time grid whose overlapping events sit in lanes or stack.

Media and tools

  • MediaA picture in a frame: eight ratios, three captions that never sit on a bare photo, loading and failed states.
  • CarouselSlides that scroll and snap, with buttons, dots and a counter underneath. Auto-advance is off until asked for, and always has a pause.
  • FilmstripA strip of thumbnails that chooses what the big picture shows: one at a time, native radio buttons, arrow keys.
  • GalleryA bento grid of pictures on one square cell grid: 1, 2 wide, 2 tall or 2 by 2. Built on the card grid, no masonry, no lightbox.
  • ToolbarA tray of round tool buttons with their names underneath: one tab stop, arrow keys, and buttons to scroll when it overflows.
  • ScrubberA ruler-and-thumb slider for exposure, warmth and seek bars: a native range with a readout and step buttons, never drag-only.
  • SwatchPick one colour from a set: round chips, each with its name, the chosen one marked by a check, a second ring and an underlined name.
  • TimelineClips along time with a playhead: a keyboard-operable track where every drag has a button or a key.
  • PlayerPlay, pause, seek and mute for a native audio or video element, with the browser’s own controls kept as the fallback.

Accessibility

  • ChecklistThe per-element definition of done, then WCAG 2.2 A and AA row by row: the rule, where the guide meets it, and which check proves it or that only a person can.
  • TestingHow this repository tests: the lint, the contrast matrix, the accessibility gate, keyboard specs, the design probe and screenshots. How to run each, what each can and cannot catch, how to read the reports and how to extend them.
  • ManualThe real-device pass no tool can make: iPhone VoiceOver, Android TalkBack, Dynamic Type and font scale, 400% zoom and text spacing, Windows High Contrast, Voice and Switch Control. Scripts, what a pass looks like, and what is not verified.
  • PatternsA keyboard pattern index: which element follows which WAI-ARIA Authoring Practices pattern or native behaviour, the keys it answers to, its tab stops, and the spec that presses them.

Project

  • StatusWhere every element stands: what the automated checks found, whether a person has reviewed its screenshots, what is still open, and how the table is kept.
  • DecisionsThe choices still waiting for the owner, and the ones taken by default so work could go on: what the guide does now, why, and which file to change to reverse each.
  • ReferencesFor each reference screen and repository the owner supplied: what idea was taken, what was left behind and why, and what could not be read.
  • ContributingHow to add the next example screens: the gate pipeline, the prompt to give an agent, the pull request checklist, and how to add a palette, a tone, an icon or a corner style.
  • ChangelogWhat changed in each version: the owner's sheet, the re-foundation, and what has been added since.
  • AuditWhat was wrong with the Flashcards style sheet v0.1, how it was found, and what was done about each finding.

Where it comes from

This guide is the owner's Flashcards style sheet v0.1, generalised. The type, space, line, shape, hit-target and focus tokens, the role names (--paper, --ink, --tone-1…6), the .card element and its ten variants, the gates and the checker rules are theirs. Added on top: real colour (dark mode, high contrast, six palettes) with contrast verified in a browser, an accessibility test gate, and the elements that came from the reference screens.
