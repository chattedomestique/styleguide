Components

Keypad

A keypad is for entering one amount with one thumb: send money, top up, set a goal. Twelve round keys in the order every phone uses, a big live number above them, and a confirm button that stays off until there is something to confirm. Every key is a real button, and a hardware keyboard works too.

When to use

Do

Use it where the amount is the whole screen and people enter it once, on a phone. Put the limit where they can see it ("Available: $2,568.00") and let the keypad refuse a number above it, out loud.

Don't

Use it for a PIN, a password or a one-time code. A custom pad blocks paste and password managers, which fails WCAG 3.3.8: use a native <input type="password" inputmode="numeric" autocomplete="one-time-code">. For a number inside a longer form, a plain amount input is better.

Examples

Amount in dollars

Press the keys, or type on a hardware keyboard: digits, . or ,, Backspace. The number is grouped and given its currency symbol by Intl. It stops at two decimals and at the data-max of $5,000, and says so. Hold the delete key to keep deleting.

Available: $2,568.00. Up to $5,000.00 a day.

Whole numbers

data-decimals="0" switches the point key off (it stays in place, dashed, so the layout never changes). Here there is no currency, three digits at most, and a minimum of 5 before the button works.

20

At least 5, at most 999.

In context: send money

A wallet screen: who it goes to, the amount, then the pad. Note the order: 1 2 3, 4 5 6, 7 8 9, then the point, 0 and delete. Any other order breaks the muscle memory of everyone who has ever used a phone, and keys that touch are how people mis-tap a payment; here the order is the standard one and there are 12 px between keys.

States

The display is a readout, not a field: it has no focus and no caret. Empty shows a muted zero; a refused key press doubles the display's frame for a moment and is announced in words. The confirm button is aria-disabled until there is an amount, so it stays focusable and its reason (aria-describedby) can be read.

What the standards ask of a keypad

WCAG criteria that apply to a custom numeric keypad
CriterionHow the keypad meets it
1.3.2 Meaningful sequence, 2.4.3 Focus orderThe DOM order is the phone-standard visual order: 1 2 3 / 4 5 6 / 7 8 9 / point 0 delete. Nothing is reordered with CSS.
2.1.1 KeyboardEvery key is a native <button>: Tab and Enter / Space. Typing digits, the point and Backspace also works.
2.5.1, 2.5.7 Gestures, draggingA tap is the only gesture. Hold-to-repeat on delete is an enhancement, and every delete also works by tapping.
2.5.2 Pointer cancellationKeys act on click (the up event), so sliding a finger off a key cancels it.
2.5.3 Label in nameThe visible text of a digit key is its name. The point is punctuation, so its name is spoken ("Decimal point"); the delete key is an icon with an action name.
2.5.8 Target size, and the house 8 px gapKeys are up to 88 px circles (never under 44) with 12 px between them, the same both ways.
3.3.1 Error identificationA refused press is announced in words and the display shows a second frame; nothing is lost and nothing changes silently.
3.3.4 Error preventionThe keypad only fills the amount. Follow it with a review step before money moves (see forms).
3.3.8 Accessible authenticationNot for PINs or passwords. A keypad that cannot be pasted into or filled by a password manager is a cognitive-function test.
4.1.3 Status messagesThe display is an <output>: a polite, atomic live region that reads the whole amount after each key.

Anatomy

  1. Label (.keypad__label): what the number is. The display is labelled by it.
  2. Display (<output class="keypad__display">): a 2px rectangle, figure type sized from the keypad's own width (cqi), tabular, right-aligned. aria-live="polite" and aria-atomic="true".
  3. Hint: the limit or the balance, in .t-meta; the confirm button points at it with aria-describedby.
  4. Keys (.keypad__keys[role="group"] of .btn.keypad__key): a 3-column grid of circle buttons, 12 px apart, each at most 88 px. They fill, lift and sink like every button.
  5. Confirm (optional, data-sg-keypad-confirm): an ordinary primary button that the keypad keeps aria-disabled until the amount passes data-min (default: above zero).
  6. Hidden input (optional): receives the plain value (12.5) for a form post.

API

Keypad attributes and events
Attribute or APIValuesEffect
class="keypad" + data-sg-keypadwrapperA size container and a grid; data-sg-keypad turns on 34-keypad.js.
data-key0–9, ., back, clearOn a button: which key it is.
data-currencyISO 4217 codeSymbol and its side, grouping and the decimal separator, all from Intl in the page language. The point key shows the language's separator.

Accessibility

Keypad keyboard and screen reader behaviour
InteractionBehaviour
TabThrough the keys in reading order, then the confirm button.
Enter / SpacePresses the focused button. That is how keyboard-only people use the keys, so Enter is not a global "confirm"; the confirm button is its own stop.
0–9, . ,, Backspace, DeleteEnter and delete the same way the keys do, while focus is anywhere inside the keypad.
Screen reader"Number pad, group. 1, button. 2, button… Decimal point, button. Delete last digit, button." After each key the whole amount is read: "$12.50".
RefusalsA press that is not allowed leaves the amount alone and is announced ("Maximum is $5,000.00", "Only 2 decimal places").
TouchKeys up to 88 px, 12 px apart; press feedback starts on the first frame (fill and sink, 130 ms). No gesture.
Zoom / text sizeThe display and the keys are sized from the keypad's width and rem; at 200% text they shrink rather than clip, and the display wraps.
Reduced motionKeys do not travel; the fill change stays.
Forced coloursKeys are circle buttons with real borders; raised and focused keys get a 4px Highlight outline; the display keeps its frame.
No JavaScriptThe keys do nothing without the script. Offer a native inputmode="decimal" field as the baseline and enhance.
