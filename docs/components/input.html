Components

Input

A native text field, made easy to see, easy to hit and easy to fill in: 16 px text so iOS does not zoom, a 2px ink frame, and the right keyboard for what you are asking. A field holds what you type, so it is a rectangle; the buttons inside it are circles.

When to use

Do

Pick the type, inputmode and autocomplete that match the data, so phones show the right keyboard and browsers can fill it in. Put every input in a field with a visible label.

Don't

Use the placeholder as the label, block paste, or use type="number" for things that are not quantities (card numbers, postcodes, amounts): it adds spinners, drops leading zeros and breaks formatting.

Examples

Text

Sizes

The default is 44 px: a text field has no invisible hit area to grow, so its box is the target. Large is 56 px. Text is 16 px (20 px large). data-width caps the width of short answers.

Types

Each native type brings its own keyboard, validation and picker. The date and time controls are the browser's own pickers (the best mobile UI there is), with only the box restyled so they match the rest of the form.

Password with show / hide

The toggle is a real button with a fixed name, Show password; aria-pressed carries the state, so the label never changes (APG toggle button). The icon changes shape as well, and the button fills when it is on. Pasting and password managers must keep working (WCAG 3.3.8), so nothing here blocks either.

At least 12 characters. Pasting is fine.

Icons, prefixes and suffixes

Adornments live inside the frame. The group is the bordered thing and the input inside it is borderless, so a prefix like "CHF" or a suffix like "kg" can be any width and the ring, the error and the disabled look are still drawn once, round the whole box. A unit belongs in the label too ("Weight in kilograms"), because the adornment itself is decoration.

kg

Search

A search field is a group with a magnifier in the start slot and a clear button in the end slot. The magnifier is decoration; the name comes from a label (visually hidden here, because the placeholder says what to type). The native cancel button is a 13 px target, so a proper clear button replaces it and appears only while there is text. Wrap a real search in <form role="search">.

Search bar: back, field, action

The app bar from the calendar reference: a circular back button, the search field taking the space that is left, and a circular action. .input-bar is the row, and it stays one row, at one height, at every text size: the circles keep their 44 px, the field is 44 px tall beside them (at 200% text its words are set solid so they still fit) and takes the rest of the width. The circles are ordinary buttons.

Amount

One big, tabular number: the hero of a "send money" screen. It is a plain text input with inputmode="decimal" (not type="number"), a currency symbol in front, and no formatting of its own: group digits, limit decimals and parse with Intl.NumberFormat in your app. The figure grows with the reader's text size until the box would no longer hold a ten-character amount, then it stops: it is sized from the field's own width, so the amount is never cut off. For a tap-only amount entry see the keypad.

$

Textarea

Grows with what you type where the browser supports field-sizing: content; everywhere else it is a box of rows lines that can be dragged taller. Either way it keeps a sensible minimum and maximum.

States

Every state has a cue that is not colour. Invalid gets an inner second frame (and the error message has an icon and words); read-only is a recessed value, not a blank; disabled is dashed and faint, the house look for "not here". Tab into the first field to see the focus ring.

These make the right keyboard appear (inputmode, enterkeyhint), let the browser and password managers fill the field (autocomplete, WCAG 1.3.5 Identify Input Purpose) and stop it "correcting" what you typed (autocapitalize, spellcheck).

Anatomy

  1. Frame: --bw (2px) in --line, --radius-ctl, filled with --paper. Flat: a field at rest casts no shadow. On a group, the group is the frame.
  2. Text: 16 px, tabular figures for numbers and dates. The placeholder is --ink-mute (4.5:1) and only ever a hint.
  3. Start slot (optional): an icon or a prefix, decorative, ignores taps. An icon stays 20 px at any text size; a prefix in words grows with the text.
  4. End slot (optional): a suffix, or one or two 36 px circle buttons (clear, show password) with 44 px hit areas that fill on hover and focus. They stay that size at any text size.
  5. Focus ring: the global ring plus paper halo round the whole box.
  6. Error frame: a --bad-ink frame and a second inner frame. The message under it carries the icon and the words.

Accessibility

Input keyboard and screen reader behaviour
InteractionBehaviour
Tab / Shift+TabMoves to and from the field; then to its clear or show buttons, which are real buttons.
TypingNative: selection, cut, copy, paste, undo, IME, spellcheck (where allowed). Nothing is intercepted.
EnterSubmits the form (the enter key on a phone shows the enterkeyhint label).
Esc in type="search"Clears, in browsers that do it natively.
Screen reader"Label, edit text". Required, invalid and described-by are announced; the show button reads "Show password, toggle button, not pressed".
TouchEvery input is at least 44 px tall; clear and show buttons have 44 px hit areas that do not overlap.
ZoomText is at least 1rem, so iOS does not zoom on focus, and it grows with the reader's text size. The side padding, the icon in the start slot, the clear and show buttons and the date picker's button stop at their 100% size, so the value keeps the room: "03/14/2026" fits a 390 px phone at 200% text. A field is still one line, so a value wider than the box ends in an ellipsis: keep values you show short, and show a chosen person or place as words that can wrap (the recipient row in the example above), not as a filled-in field. Known limit: a native date or time value is drawn by the browser and cannot wrap, so in a field narrower than about 7rem at 200% text its last characters can be cut off. Give date and time fields the full width of the screen; every segment still takes keyboard input and the picker still opens.
Forced coloursThe frame is the control; invalid gets a heavier border; disabled uses the system grey; the group's ring is a system-colour outline.
No JavaScriptEverything but clear and show / hide works. Those buttons are hidden (@media (scripting: none)), not left dead.
