Components

Empty state

Every screen that shows data has four ways to show none: nothing yet, nothing found, something broke, no connection. Each one says what happened in a sentence, says what to do in a sentence, and puts the fix in one button. A blank screen looks like a bug.

When to use

The four empty states, what to say and how to announce them
StateSayPrimary actionAnnounce
Empty: first use, nothing createdWhat this place is for and how it fills up.Create the first one (Add deck)Nothing: it is page content.
No results: a search or filter matched nothingWhat was searched. Suggest a fix.Clear search / Clear filtersPolite: SG.announce("No results for fox"), or a role="status" that already exists.
Error: the load or save failedWhat failed, without blame, and that nothing was lost.Try againAssertive: role="alert", or SG.announce(msg, { assertive: true }).
Offline: no connectionThat the device is offline and what still works.Try again; or open saved itemsPolite, when it changes. Offline is a state, not an emergency.
Do

Write for someone mid-task: "Couldn't load your decks. They are safe on this phone. Try again." Keep what the person typed. Make the button do the obvious next thing.

Don't

Decorate. An illustration that could sit on any product's empty screen says nothing here. The icon names the kind of empty; the words do the rest. No art, no jokes, no blame.

Examples

The four states

Built on the card's ghost idea: a dashed frame means "nothing here yet". An error or an offline notice is not empty, it is something that happened, so a tone makes it solid and filled. Each has its own icon shape, so colour is never the only cue. The one primary action is the filled button (data-variant set to primary); a quiet alternative takes the card's tone as an outline (set to tone, which reads the tone from the card). Two actions share one width, side by side or stacked. The cards in a row line up at the top.

Full screen

data-layout="page" fills what the app shell leaves between the app bar and the dock, and centres the content. Set --empty-page-h to fit a preview frame (this one uses 25rem). It is a minimum, not a fixed height, so 200% text scrolls instead of clipping. The two actions sit side by side when both fit at the width of the wider one, and otherwise stack at that one width, so the pair never shows two different sizes.

Announcing and recovering

  • When the state appears because of an action (search, filter, refresh, a dropped connection), tell people without moving focus (WCAG 4.1.3). Either insert the state into a container that already exists with role="status" (role="alert" for errors), or keep the markup plain and call SG.announce(). Do both and it is read twice.
  • When it is simply what the page is (first load, no data), it is content, not an event. No role.
  • If the thing that had focus disappears (the "Clear search" button you just pressed), move focus on purpose: to the field, to the heading of the new content, or to the first result.
  • Offer recovery: a retry that works, a way to keep going offline, a path back. The action is a real <button>, or a link if it navigates.
  • Preserve data. An error state that clears the form is a second error.

Anatomy

  1. Card (.card.empty): the 2px frame is the card's own, dashed for "nothing yet", solid and filled with a tone for "something happened". Padding is on the .card__body, as for every card.
  2. Icon tile (.empty__icon): the owner's icon tile, a 2px-framed square slot in --radius-tile, with a paper fill so it reads on the dashed canvas and on any tone. 56px (72 in the page layout, 44 in the list layout), the same at every text size. aria-hidden, because the title says the same thing in words.
  3. Title (.card__title): what is true now, in a short sentence. A real heading, at the level that fits the page.
  4. Message (.card__text): what to do, or why. About 36 characters wide, so it never becomes a paragraph.
  5. Actions (.empty__actions): one primary, at most one quiet alternative. Side by side at one shared width (the widest label’s) while the row has room for that; otherwise stacked, every button as wide as the widest (measured by 66-empty.js, which writes data-fit="row" or "stack"; without JS the row wraps).

API

Empty state classes and attributes
Class or attributeValuesEffect
class="card empty"Container. Parts: empty__icon, card__title, card__text, empty__actions.
data-layout(default), page, listCentred block, full screen, or a compact left-aligned unit.
data-tonebad, warn, info, ok, 1 to 6Solid and filled instead of dashed and empty. The primary action is data-variant="primary"; a quiet alternative is data-variant="tone", which takes the card's tone.

Accessibility

Empty state keyboard and screen reader behaviour
InteractionBehaviour
Screen readerReads the heading, the message and the button, in order. The icon tile is hidden: it adds nothing the words do not say. See above for when to announce.
KeyboardThe actions are ordinary buttons in reading order. After a state replaces focused content, move focus on purpose.
TouchButtons are 44px or taller with 8px between them.
ColourNever the only cue: a different icon shape plus words. The wire palette keeps all four distinguishable.
Zoom / text sizeThe words grow with the reader's text size and wrap between words; the icon tile and the card's insets stop at their 100% size, and a button's icon stays beside its label. The page layout has a minimum height, not a fixed one.
Forced coloursThe card's border (dashed or solid) and the tile's border stay in CanvasText.
