Components

Toolbar

A toolbar is a tray of tools you reach for again and again: Crop, Light, Colour. Each is a round Button with its name under it, because a bare icon asks you to guess. The tray is one tab stop and the arrow keys move inside it, so a keyboard user does not tab through twenty buttons to get past it.

When to use

Do

Use it for three or more related controls that act on the same thing, like the tools of an editor. Keep every tool labelled, and put the same tools in the same order on every screen.

Don't

Use it to move between pages (that is navigation: links, with aria-current) or to switch panels of content (that is tabs). Do not leave the names off to save room: scroll instead.

Examples

A tray of tools

Pick one of a group: each tool is a role="radio" Button inside a role="radiogroup", and the one that is on has a filled circle, a doubled frame (a 2px ring inside its border, so it stays the size of the other tools) and an underlined name; only the tool that is on is filled (a pointer over another one raises it, a press tints it). Seven tools do not fit on a phone, so the tray scrolls and the two scroll buttons appear, small (36px, with a 44px target), one on each side of the tools on the same row. The tray shows whole tools only: it pages, each page the tools that fit, spread out to fill it, so no circle and no word is sliced at the edge, and forward brings the next page. The buttons disappear when everything fits.

Toggles, actions and groups

Buttons that switch something on and off use aria-pressed; buttons that just do something need nothing. A .toolbar__sep divides groups. A tool that cannot be used right now is aria-disabled, not disabled: it keeps its place in the arrow-key order, so a keyboard user finds it and hears why.

Redo: nothing to redo yet.

Tones and dark stages

Put data-tone="1" to "6" on the tray to tint it; the buttons stay paper, so they keep their contrast. Editors are usually dark so the picture is the brightest thing on screen: make the tray an island with data-theme="dark" and every role, the ring included, follows.

In context

An editor screen: an app bar with the photo's name and Save, the photo, and the tray underneath. Choosing a tool swaps the rest of the screen to that tool's controls (see Scrubber and Swatch).

Harbour at dawn

Anatomy

  1. Tray (.toolbar): a 2px frame, a rectangle (square or soft with data-corners). It holds; the circles inside act.
  2. List (.toolbar__list, role="toolbar"): the scroller and the one tab stop. It has an aria-label. Its 8px padding leaves room for the focus ring and the hard shadow, which overflow scrolling would otherwise clip. While it overflows it pages: each page is the cells that fit whole, spread evenly to fill it.
  3. Tool (.btn circle, 44px at every text size) in its cell (its label's width plus 4px a side, never under 52px; cells 4px apart): a Button. Icon 20px, decorative. A toggle or radio tool is filled only when it is on, its frame doubled inside its border.
  4. Label (.toolbar__label): a <label for> the button, under it, in sentence case. It is the accessible name and a second, larger place to tap. Underlined when the tool is on.
  5. Separator (.toolbar__sep): a 1px rule between groups.
  6. Scroll buttons (.toolbar__scroll, data-size="sm"): back and forward, for people whose pointer does not swipe. 36px circles with 44px targets, so the tools keep the room, one on each side of them, on the same row, centred on their circles, never over a tool. Each press goes one page. aria-disabled at either end. tabindex="-1", so the toolbar stays one tab stop; keyboard users scroll by arrowing.

API

Toolbar classes and attributes
PartAttributeEffect
.toolbardata-tone 1 to 6, inkTints the tray. On ink the focus ring follows the surface.
.toolbar__listrole="toolbar", aria-label (required)The toolbar and the scroller. Buttons inside get the roving tabindex.
.toolbar__grouprole="radiogroup", aria-labelA set of tools where one is on. Its buttons are role="radio" with aria-checked.
.toolbar__itemA circle Button and its .toolbar__label. The label's for must match the button's id.
Button in an itemaria-pressed, aria-checked, aria-disabledOn is a filled circle with its frame doubled inside. See Button.
.toolbar__scrolldata-dir="back|forward", data-size="sm", hiddenStart hidden; the script shows them only when the list overflows. One on each side of the list, on the same row; each press goes one page of whole tools.
Button in an itemdata-toggleOptional: pressing flips aria-pressed. Skip it when your app owns the state.
SG.toolbar.init(list)Wire a toolbar you added after load (existing ones are found automatically).
SG.toolbar.fit(tray)Re-measure one .toolbar now: which scroll buttons show, and its pages of whole tools. It runs by itself when the tray or a label changes size and when fonts load.
SG.toolbar.page(tray, step)1 | -1Go one page forward or back (what the scroll buttons do).

Accessibility

Toolbar keyboard and screen reader behaviour
InteractionBehaviour
TabEnters the toolbar on the tool last used (or the one that is on, or the first); the next Tab leaves it. The scroll buttons are not tab stops: arrowing to a tool scrolls it into view.
Left RightMove between tools and wrap around (mirrored in right-to-left). The focused tool scrolls into view.
Home EndFirst and last tool.
Enter SpacePress the tool. A radio turns on and the others turn off; a toggle flips. Arrow keys never change what is on, only where focus is.
Screen reader"Photo tools, toolbar". Each tool: "Light, radio button, checked, 2 of 7" from the visible label. Toggles say pressed or not pressed; aria-disabled says unavailable, and the reason is read from aria-describedby.
TouchThe circle is 44px and the words under it are part of the same target. Swiping scrolls the tray a page at a time; the scroll buttons are the alternative to swiping (WCAG 2.5.1).
Zoom / text sizeThe labels grow with the text and wrap at their spaces inside their cell (a single word is never broken); the circles, their targets, the gaps and the cells' 52px minimum keep their 100% size. The tray pages at 320px (two whole tools) and at 200% text (two whole tools on a 390px phone), and the scroll buttons stay beside the tools on the same row, so a person who cannot swipe can still reach every tool.
Reduced motionNo lift travel; the shadow, the press tint and the on fill stay. Pages jump instead of gliding.
Forced coloursThe tray and every Button keep a real border; on is a 4px frame.

Tokens used

--paper, --ink, --ink-faint, --line, --line-soft, --tone-bg, --tone-ink, --bw, --bw-thin, --radius-card, --chrome-hit, --chrome-ctl, --chrome-ctl-sm, --chrome-1, --chrome-2, --type-meta, --lift, --fill, --dur-press. Everything else is the Button's.
