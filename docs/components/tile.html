Components

Tile

The square quick action: Send, Bills, Top up, Study. An icon and a name on a field of colour. You press it, so it has a 2px frame and a hard shadow that appears when it can be pressed; the field is the tone, so a row of tiles gives a screen its colour.

When to use

Do

Use four or eight of them for what people do most, each with a word under the icon, in a .tile-grid. Put the most used first.

Don't

Show a tile with only an icon, use tone to say which one matters, or build your main navigation from them. That is a dock.

Quick actions

A tile is a link or a button, so it is an <a> or a <button>. Put them in a .tile-grid: four to a row while four fit, two to a row when they do not (a narrow phone, large text), and never three with a lonely fourth. Give it two, four, eight or twelve tiles. The icon is a mask in the text colour, directly on the field: no circle behind it.

Tones

The six slots, the inverted ink tone, the four status tones and no tone at all work. A tile that is on fills with the tone's own solid (--tone-fill); with no tone it fills with the accent. data-emphasis="bold" gives a saturated field. A tone is rhythm: the label says which tile matters, and a status tone still needs its words.

Badge

A count in the corner, for what is waiting: bills due, unread, new. It is a paper pill with an ink frame, so it reads on any field, filled or not, and it is chrome like the icon beside it: 24px at any text size. Put the unit in visually hidden text so the tile's name is Bills, 3 due. A dot with no number is colour alone and is not offered. A badge needs room beside the icon (four to a phone's row, a tile is about 65px, and even a "3" covered the icon), so a .tile-grid that holds a badge keeps its tiles 6rem or wider: two to a row on a phone, four on a wider screen.

As a toggle

A tile that picks something is a button with aria-pressed. On is the only filled state: filled, and the frame doubles, so it never depends on the fill being dark. Hovering or pressing a tile that is off never fills it, so nothing looks chosen until it is.

States

The same two numbers as the button: --lift (0 flat, 1 raised) and --fill (0 the tone's field, 1 its solid). A tile can be on, so only on is filled: hover and keyboard focus raise it (a keyboard user sees what a mouse user sees), pressing puts it back down with a light tint, and the fill with its doubled frame is kept for a tile that is on. Each specimen below is the same Send tile, named by the caption under it. The is-* classes only force a state for this page.

Caption tiles

A field (colour, an icon or a photo) closed by a bar that carries the name. Text never sits on the photo, so its contrast does not depend on what the photo is. Hover raises a caption tile like any tile; when it is on, the bar swaps polarity where a quick tile fills. A caption needs more room than a quick action, so its grid asks for 8rem a tile: two to a row on a phone, four on a wider screen.

Anatomy

  1. Frame: 2px --line, --radius-tile, a real border so forced-colours mode draws it.
  2. Field: --tone-bg, or --paper with no tone. --fill mixes it toward --tone-fill (or --accent): 15% while pressed, all of it when on.
  3. Icon: a 24px mask at the start, in the text colour, decorative (aria-hidden).
  4. Label: --type-ctl, 14 to 20px with the tile's width, at the bottom. Wraps between words; never truncated.
  5. Padding: 10% of the tile, between 8 and 16px; chrome, so it does not grow with text.
  6. Badge (optional): paper pill with an ink frame, top end. Chrome: 24px with 14px figures at any text size, like the icon beside it.
  7. Hard shadow: 4px, zero blur, appears with --lift. It means "you can press this".

API

Tile attributes
AttributeValuesEffect
class="tile-grid"--tile-min (4rem), --tile-gap (12px)The grid for tiles: four to a row while four of --tile-min fit, two to a row otherwise. For sets of 2, 4, 8 or 12. A grid that holds a badge takes 6rem, so the badge never covers the icon.
class="tile"The tile. An <a> or a <button>. Needs a width from its parent (a grid cell). Square; a tile wider than 10rem stops at 10rem tall.

aria-currentpage, trueThe tile for where you are. Same look as on.

Accessibility

Tile keyboard and screen reader behaviour
InteractionBehaviour
TabEach tile is one tab stop, in DOM order. The ring (3px, offset 3px) plus a paper halo stays visible; the tile lifts exactly as on hover, and is not filled unless it is on.
Enter / SpaceA link follows on Enter; a button activates on both. Native elements give this for free.
Screen reader"Bills 3 due, link". A toggle adds pressed / not pressed; a current tile adds current page. The icon is hidden.
ColourThe tone is never the message. On is fill and a doubled frame; the badge is a number and a word.
Touch64px square or more in a .tile-grid, well beyond 44px, with 12px between targets. A press shows at once as a tint.
Zoom / text sizeThe grid's minimum is rem, so four to a row become two to a row as text grows (never one huge tile a row, never three and one). The padding stays 8 to 16px, so labels keep the room. A wrapping label makes the tile taller, never clipped, and the tiles of a row stay one height.
Reduced motionNo travel on hover (the tile stays in place); the shadow, the pressed tint and the fill still change.
Forced coloursFrame is ButtonText; hover and focus get a 4px Highlight outline; on and current get a 4px frame.
