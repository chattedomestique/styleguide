Motion

Motion explains a change: something arrived, something moved, a press registered. It is never decoration the reader has to wait for, and when a reader asks for less of it the guide makes it gentler, not instant.

Gate 4

The owner's pipeline moves every element through gates: brief, wireframe, states, colour, motion, freeze. Motion comes after the states and the colour are settled, because animation on an unsettled layout hides the problems the earlier gates are there to find. tests/lint.mjs carries the rule (motion before gate 4 opens fails); it is open in this guide, and Card and Button have both been through it. What moves is deliberately small:

  • Only transform, opacity and the two registered numbers animate. --lift and --fill carry the hover, focus and press changes (see Interaction). Nothing animates layout.
  • One transition per element. transition: all is banned: list the properties.
  • No springs and no overshoot. The curves below are smooth and settle; nothing bounces.
  • Every travel is multiplied by --move, so one switch turns distance into a fade.

Durations

Four durations cover everything. Press Play: each dot makes the same move with a different duration. Under reduced motion the dots stop travelling and only change colour, which is exactly what a component does.

--dur-press and --dur-hover do not change under reduced motion, because they are colour and shadow changes, not travel. Only the two that describe movement get shorter.

Easing

Three curves. Things that arrive use --ease-out: fast first, settling slowly. Things that leave use --ease-in, and less time than they took to arrive, so they get out of the way. --ease-flip is for a flip: slow, quick in the middle, slow. The same move, at --dur-move, with each curve:

--ease-outThings arriving
--ease-inThings leaving, in less time
--ease-flipThe card flip

--ease-outcubic-bezier(0.22, 1, 0.36, 1)Everything arriving; the default for a hover or press transition.
--ease-incubic-bezier(0.4, 0, 0.7, 0.2)Things leaving. The sheet below takes --dur-hover (200ms) to leave after --dur-enter (320ms) to arrive.
--ease-flipcubic-bezier(0.83, 0, 0.17, 1)Rotation: the flip of a flashcard. Not for travel.

--move: travel becomes a fade

--move is 1 normally and 0 under reduced motion. Every component multiplies each distance it travels by it, so a slide or a rotation collapses to nothing while the opacity and colour changes stay. Nothing is written twice.

/* a pressable lifts by 2px: none of it under reduced motion */
transform: translate(
  calc(var(--lift) * var(--space-1) / -2 * var(--move)),
  calc(var(--lift) * var(--space-1) / -2 * var(--move))
);

/* a sheet arrives from below: a fade alone under reduced motion */
transform: translateY(calc(var(--move) * 2.5rem));

Reduced motion: gentler, not instant

Someone who asks for reduced motion is asking for less movement, not for a page that jumps. Jump cuts are what a large part of that audience did not ask for, so durations never drop to zero. What the two blocks in 60-motion.css do:

What reduced motion changes
TokenNormalReducedEffect
--move10No travel, rotation or scale that a component multiplies by it.
--dur-move520ms200msThe remaining fade is brief.
--dur-enter320ms180msArrivals are short fades.
--anim-spinsg-spin 800ms linear infinitesg-pulse 1400ms ease-in-out infiniteA rotating spinner becomes a slow opacity pulse.

Colour changes, fills and the appearance of a shadow are not travel, so they stay. A button still fills on hover; it just stops moving.

The in-app override

The default follows the operating system (prefers-reduced-motion: reduce). An app should also offer the choice itself, because some people cannot change OS settings and some want full motion on a device set to reduce. data-motion on <html> decides:

How the OS setting and data-motion combine
data-motionOS saysResult
absent (System)reduceReduced
absent (System)no preferenceFull
reducedanythingReduced
fullanythingFull. This deliberately overrides an OS request to reduce.

The media-query block and the attribute block in 60-motion.css are copies of each other, and lint fails if they drift. SG.prefs.set('motion', 'reduced' | 'full' | 'system') applies and saves the choice; the buttons at the top of this page call it. Smooth scrolling follows the same rule: it is on only when the OS has no reduce preference and the app has not chosen Reduced.

When JavaScript must check

CSS already respects --move. Script that animates for itself, through the Web Animations API, View Transitions, a canvas loop or scrollIntoView, does not: it has to ask. SG.motion.reduced() mirrors the CSS exactly: data-motion="reduced" forces true, "full" forces false, otherwise the OS decides.

const root = getComputedStyle(document.documentElement);
const ms = parseFloat(root.getPropertyValue('--dur-move'));   // 520, or 200 when reduced
const easing = root.getPropertyValue('--ease-out');

const frames = SG.motion.reduced()
  ? [{ opacity: 0.35 }, { opacity: 1 }]                            // a fade
  : [{ transform: 'translateX(0)' }, { transform: 'translateX(8rem)' }];  // travel
box.animate(frames, { duration: ms, easing, fill: 'forwards' });

Loading indicators

Loading uses var(--anim-spin), never a hand-written keyframe, so it becomes a pulse by itself. A spinner is paired with words (Loading decks), because motion alone tells a screen reader nothing, and it stops when the work does. A button that is working uses aria-busy="true" and gets one for free (see Interaction).

Loading decks

Rules

  • Transform, opacity and the two numbers. Nothing else moves.
  • Multiply travel by --move. Reduced motion is a plain fade or fill change, never a jump.
  • Never zero a duration to "turn motion off". Shorten it.
  • Nothing flashes more than three times a second (WCAG 2.3.1).
  • Anything that moves for more than five seconds (a marquee, an autoplaying carousel) has a visible pause control (WCAG 2.2.2). A loading indicator is exempt only while loading is actually happening.
  • Every gesture has a tap or key equivalent (WCAG 2.5.7). Motion never gates function.
  • Check in script with SG.motion.reduced() before animating from JavaScript.

Add or change a motion token

  1. Put it in src/tokens/60-motion.css with a comment saying what it is for.
  2. If reduced motion should change it, set it in both blocks, @media (prefers-reduced-motion: reduce) and :root[data-motion="reduced"], identically.
  3. Use it in a component through a single transition that names its properties. Write the spec with reducedMotion and assert the travel is gone.
  4. Document it here, in the durations or easing table.

Tokens used

--dur-press, --dur-hover, --dur-enter, --dur-move, --ease-out, --ease-in, --ease-flip, --move, --anim-spin, --lift, --fill.
